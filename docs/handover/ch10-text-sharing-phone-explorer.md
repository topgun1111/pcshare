**PC side (`pcprint.py` v26 + `core/PcText.kt`)**: `POST /p/clip` (also `/clip`) stores texts in `%APPDATA%\LANSharePrint\inbox.json` (max 300 / 2 MB), optional copy to the clipboard (PowerShell `Set-Clipboard`; setting "Copy received text automatically", default off, also the opt-in for quiet pushes) and opens the **LANShare Text** window (setting "Open this window on new text", default on, at most every 5 s). Localhost only (the window): `GET /clip?since=N`, `POST /clip/send {to,text}`, `/clip/delete {id}`, `/clip/settings {autocopy,popup}`; other LAN devices cannot read the inbox. Devices to send to: the service listens for the phones' UDP beacons (port 48555, `SO_REUSEADDR`) and keeps those heard in the last 90 s; a phone that sends text here registers itself; `/clip/send` only talks to devices in that list. Window: `pcprint.py --text` or the **Text** button (single instance, named mutex): list (double-click = copy), Copy / Open link / Delete / Clear all, device drop-down + box + Send (Ctrl+Enter), the two switches. `/ping` has `"clip": true`. Setup adds a UDP firewall rule `LANSharePrint-Beacons` (48555, LocalSubnet + tailnet) - run the new file once so Windows asks. Tested on Linux with a stub phone; the Tk window only against mocked tkinter; Windows clipboard / popup / firewall not run.
**Phone side (`core/PcText.kt`, `TextSend`)**: a PC is not a LANShare peer, so every ~30 s (on demand from `TextSend.online()`) the known addresses (devices, saved SMB hosts, pins, ARP neighbours) get `GET :8799/ping`; a reply with `clip:true` makes that host a target "<PC> (PC)", id `pc:<ip>`, port 8799, shown wherever phones are (inbox, picker, default device, Direct Share, tile, share sheet) because `TextSend.online()` / `find()` merge both lists; `RemoteFs.pushClip` posts to its `/p/clip` unchanged. Old pcprint (404) -> "pcprint.py ... is older than v26". The phone must be on the same subnet as the PC (or both on the tailnet).

### 10.2 Phone Explorer (phone storage in Windows Explorer, one tap)
**Status 2026-10-18**: coded, NOT compiled, NOT run on a device or on Windows. Drawer row **Phone Explorer** = one tap: `peOpenOnPc()` (ui.html) starts the phone's FTP share if needed, broadcasts a search for PCs (`GET /api/pcfind` -> `PePc.find`, UDP 41235, answered by `phone_explorer.py` on the PC), picks the PC (last used by name; one PC = at once, several = one-time picker) and calls `POST /api/pcphone?ip&hport&port&user&pin&name` -> `PePc.open` -> `POST http://PC:8798/open` -> the PC tool runs `explorer.exe ftp://user:PIN@<phone ip>:2121/`. Nothing to type; `pcprint.py` is NOT involved. The gear on the row opens the settings sheet `openPhoneExplorer()`: Start / Stop, address, PIN, Copy link, New PIN, QR, Read-only, Start automatically, shared folders, port, **Open on PC**.
- **Files**: `pe/FtpServer.kt` (pure JDK FTP server, port 2121, user `phone`, 6-digit PIN, LAN clients only), `pe/PeDiscovery.kt` (UDP 41234, answers the old PC tool's search), `pe/PePrefs.kt`, `pe/PeService.kt` (foreground service, notification 21, locks, `PeBoot` receiver), `pe/PePc.kt` (find / open PC), `pe/PeTls.kt` (FTPS option: one self-signed RSA-2048 certificate, 10 years, made on first use and kept in `filesDir` as `pe_tls_key.pk8` + `pe_tls_cert.der`, so an accepted fingerprint stays valid; **no handover note beyond the file header**). `MainActivity.Bridge`: `peState / peStart / peStop / peSet / peNewPin / peQr / peGrant`. `Routes.kt`: `pcfind`, `pcphone`. Manifest: `FOREGROUND_SERVICE_SPECIAL_USE`, `RECEIVE_BOOT_COMPLETED`, service `.pe.PeService`, receiver `.pe.PeBoot`. Gradle: `com.google.zxing:core:3.5.3`.
- **PC**: `tools/phone_explorer.py` (Tkinter + tray; UDP responder 41235, HTTP `/open` on 8798, LAN clients only, user / PIN validated, saves the phone in its list, opens Explorer; keep it running, allow it once in the Windows firewall); the .exe is built by `.github/workflows/build-phone-explorer-exe.yml`. Smoke tests: `tools/ftp_smoke_test.py`, `tools/ftps_smoke_test.py`.
- **Limits**: needs All-files access (the first tap opens that setting); Android 11+ keeps `Android/data` and `Android/obb` closed; router "client isolation" blocks everything; the share is independent of the LANShare service but the LANShare notification Stop still kills the whole app; a port change needs Stop + Start (read-only and the folder list apply at once).

### 10.3 Remote command (admin, off by default, password set on the PC) - owner's own devices only
**Update 2026-10-31: the app side of this chapter (`PePc.exec`, `ExecResult`, `PePc.send`, `PePc.version`, route `pcexec`) was removed - nothing has used it since the real terminal (chapter 19). `/exec` on the PC stays for old APKs only (see chapter 21 section 8).**
**Update 2026-10-30 (protocol v2, jobs)**: `POST /exec?id=<8-64 chars>&pass&cmd[&wait=<=25]` starts a job (same id never reruns); `poll=1` only asks (404 if unknown, never starts); long-poll <=20 s; answer `{done:false}` or `{done:true,out,err,code,truncated}`; job limit 1800 s (no id: legacy 300 s single answer); max 8 jobs, finished kept 15 min; `/exec?probe=1` -> `{"v":2,"exec":bool}`. Phone: `PePc.exec(...,id,poll)` = one step, `ui.html exec()` loops steps and retries network errors (`PC not reachable` = safe to retry). Details + device test list: chapter 21.
**Update 2026-10-30 (owner request): all PIN authentication removed.** `/exec` on the PC has no PIN; the only gate is the LAN-only check + the ON/OFF button ("Remote commands: ON/OFF") in the `phone_explorer.py` window (config `exec_enabled`, off by default). `PePc.exec(ip,hport,cmd)`, `Routes` `pcexec` and `ui.html openPcExec()` no longer take / ask for a PIN. While ON, any device on the LAN can run commands as the PC program (admin if elevated). Not compiled / not device-tested yet; the PIN lines below are historical.
**Status 2026-10-30**: PC side (`tools/phone_explorer.py`) finished and `py_compile`-checked this session. Phone side (`pe/PePc.kt` `exec()`, `Routes.kt` `pcexec`, `ui.html` `openPcExec()`) is coded but **NOT compiled, NOT device-tested** - next session: build the APK, fix compile errors, then the checklist below.
- **What it does**: "Remote command" button inside the Phone Explorer settings sheet -> picks a PC (reuses `/api/pcfind`), enters that PC's own "remote command PIN" (separate from the FTP PIN) + a command line, `POST /api/pcexec?ip&hport&pin&cmd` -> `PePc.exec()` -> `POST http://PC:8798/exec?pin&cmd` -> shows stdout / stderr / exit code (truncated at 64 KB).
- **PC side** (`phone_explorer.py`): new window section "Remote commands" - PIN (auto-generated 6-digit, Copy / New PIN) + "Allow the phone to run commands on this PC" checkbox (**off by default**); `/exec` on the existing port 8798 checks LAN-only + `exec_enabled` + `hmac.compare_digest` PIN match, then `subprocess.run(cmd, shell=True, timeout=60)`. **Admin**: on launch the program now tries `relaunch_elevated()` (one UAC prompt via `ShellExecute runas`; skip with `--no-admin`); title bar and a label show whether it is running elevated. `set_startup()` now prefers a Task Scheduler entry (`/RL HIGHEST`, needs the process to already be elevated to create it) so later logons start pre-elevated with no repeated prompt; falls back to the old Run-key (re-prompts every login) when not elevated.

No manifest change needed.
- **Risk, flagged to the owner**: this is a full remote-shell endpoint on the user's own LAN tool; it is PIN-gated and off by default, but anyone who learns the PIN and reaches port 8798 can run anything the PC process can. Keep the PIN private; turn the checkbox off when not using it.
