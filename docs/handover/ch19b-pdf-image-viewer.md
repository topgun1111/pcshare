## 19. PDF image viewer (multipart plan, 4 parts)

### 19.1 Goal and why (owner, 2026-11-04)
- Big PDFs open slowly even when cached and show white pages. Wanted: extract the pages once to **compressed images**, show them in a **custom viewer that behaves like the normal PDF viewer but loads instantly**. Cache folder exists -> show at once. No cache folder -> start caching (pages appear as they are made). **Everything on the phone** (no PC help). Compress images if that makes viewing faster.
- Findings (code read 2026-11-04): a v2 page cache already existed (JPEG, `PdfPageCache`), but (a) the viewer still opens `PdfRenderer` in the background and falls back to live renders, (b) white pages come from `PdfRenderer` itself (native memory / heavy pages) - the builder used the same renderer, (c) pages were stored at screen width only, so zoom went back to live rendering, (d) the viewer is a RecyclerView of live-render holders, not an image viewer.

### 19.2 The four parts (one per session; code only the next one)
1. **Part 1 - cache engine v3 (CODED 2026-11-04, not compiled).** `PdfCacheCodec` + `PdfPageCache` (see 19.3).
2. **Part 2 - image viewer widget (CODED 2026-11-04, not compiled; see 19.3b).** New `PdfPagesView.kt` (plain `View`/`ViewGroup`, no PdfRenderer): continuous vertical page column laid out from `PdfPageCache.info()` sizes, fling + overscroll, pinch zoom + double-tap + pan like the system viewer, page-number indicator, visible-page window (+-2) decoded on a small thread pool into an LRU (RGB_565 at fit width, ARGB / `BitmapRegionDecoder` tiles when zoomed beyond the cached width), thumbnail first then page, placeholder + spinner for pages not cached yet (never white), `PdfPageCache.focus` called on every page change. Self-contained so it can be tested with a folder of fake `p0001.webp` files.
3. **Part 3 - wire it into `PdfViewerActivity`.** Cache-first: `info()` + `complete` -> show `PdfPagesView` at once, never open `PdfRenderer` for display. No cache -> `attach` (starts the builder), show the view with placeholders and follow `Listener.onPage`. Remote / SMB PDFs: download first (existing path), then same. Keep `PdfRenderer` only for: print, save selected pages, OCR page text, and pages the builder gave up on (`bl` list; shown with a "page could not be drawn" tile + Retry). Overview grid reads `readThumb`. Fast scroller, page jump, title bar, JobOverlay stay. Remove the old live-render holder path from the display route once the new view works.
4. **Part 4 is split in two (one per session).**
   - **4a - isolated build process (CODED 2026-11-04, not compiled; see 19.3d).** `:pdfbuild` service runs the build; crash restart; page that crashes twice goes to `bl`.
   - **4b - management (CODED 2026-11-04, not compiled; see 19.3e).** Settings (threshold now 10 MB, image quality, "cache all PDFs"); clear cache / size shown / LRU cap for next-to-PDF folders too; cache removal when the PDF is deleted or renamed; auto-resume of a build interrupted by the APP dying (needs a small pending list in `filesDir` + a hook at app start; 4a only resumes after a crash of the `:pdfbuild` process); remove the old RecyclerView holder code if the threshold changes; device checklist for 4a + 4b; CHANGELOG; merge of chapter 19 into the main chapters.

### 19.3 Part 1 as built
- **Folder** (unchanged): PDF on phone -> `<pdf folder>/cache/<name>/`; remote / read-only -> `filesDir/pdfpages/<hash>/` (2 GB cap). Files: `meta.json`, `p0001.webp` (page), `t0001.webp` (thumbnail, 240 px wide), `.nomedia`. Tmp files end `.tmp` and are never read.
- **meta.json v3**: `v` 3, `sig` (size:mtime or key), `cw` (cached page width in px = screen width x 1.5, clamped by `maxW` / `maxPx`), `n`, `pw[]` / `ph[]` (page size in points; written as soon as the builder opened the PDF, before any image), `bl[]` (pages the renderer left white after 4 tries: not stored), `complete`.
- **Compression**: lossy WebP (`WEBP_LOSSY` on API 30+, `WEBP` below) q78 for pages, q65 for thumbs; ~30-40% smaller than the old JPEG q90 at the same sharpness for text; decode with `RGB_565` option (`read(..., fast = true)`) halves memory and upload time.
- **Builder**: sizes pass, then pages nearest to `focus(dir, page)` first (forward first, then backwards), one retry round for pages that threw, blank pages retried at 1, 1/2, 1/3 size after a 250 ms pause, then recorded in `bl`. Throttled while a viewer does live renders (old rule) but full speed for 4 s after every `focus` call. `Listener.onPage` / `onFinished` for progressive display.
- **Public API** (old calls unchanged): `attach`, `lookup`, `read(dir,pos,w,h,upscale,fast)`, `pageFile`, `status`, `isBlank`, `pdfLock`, `viewers`, `lastUse`, `MIN_BYTES`, `Hit`; new: `thumbFile`, `readThumb`, `focus`, `info` / `Info`, `addListener` / `removeListener` / `Listener`.
- **Known limits**: still the framework `PdfRenderer` (a page it renders white stays in `bl` until Part 4's isolated process retries it); no zoom beyond 1.5 x screen width from cache (Part 2 decides: live region render vs. cap); old v2 caches are deleted on first open and rebuilt.
- **Check (after the APK builds)**: open a >= 10 MB PDF twice. First open: notification "Caching PDF", pages appear in the viewer (old viewer still shown in Part 1 - speed-up visible on reopen only). `cache/<name>/` holds `p*.webp` + `t*.webp`, noticeably smaller than before; reopen shows all pages at once; `meta.json` has `pw/ph` early (open the folder while the build runs).

### 19.3b Part 2 as built (`PdfPagesView.kt`)
- Plain `View` (no PdfRenderer, no RecyclerView). `open(dir)` reads `PdfPageCache.info` (page sizes in points); until sizes exist it shows "Preparing pages" + spinner and retries every 0.5 s (up to 120 tries; `refreshInfo()` restarts). Layout = view width x page aspect + 6 dp gaps, positions in `tops[]` at zoom 1; zoom 1-5x, scroll offsets in zoomed px.
- Gestures: drag, fling (`OverScroller`), edge glow (`EdgeEffect`), pinch (focal point stays put), double-tap 1x <-> 2.5x (220 ms animation), single tap -> `onTap(x, y, page)`. Rotation / resize keeps the page in the middle of the screen.
- Bitmaps: `LruCache` by bytes (maxMemory/5, max 120 MB), never recycled on eviction. Keys `page*3+level`: 0 = fit width, 1 = cached full width (only when zoom > 1.08 and the cache is wider than the view), 2 = thumbnail (shown until the page itself is there). All RGB_565. 2 daemon threads; a task is dropped when its page left the window (visible +-3) or the document changed (`gen`). Pages not on disk are re-checked at most every 700 ms (`miss`); `pageReady(pos)` clears that. Prefetch = visible +-2 at level 0.
- `PdfPageCache.focus(dir, page)` on every page change and every 1.5 s while a visible page is still missing.
- Placeholder = dark grey tile with the page number + spinner, never white. `setBlocked(set)` swaps the spinner for "Page could not be drawn" (Part 3 reads `bl` from meta.json; `Info` does not expose it yet, add a field or read the json there). No Retry button yet (Part 3).
- API for the host: `open`, `refreshInfo`, `pageReady`, `setBlocked`, `scrollToPage(page, smooth)`, `scrollFraction` (get / set, for the fast scroller), `close`, `pageCount`, `currentPage`, `zoom`, callbacks `onPageChanged`, `onTap`, `onZoomChanged`, texts `textPreparing` / `textFailed` (no strings.xml in the app).
- **Deviation from the plan:** no `BitmapRegionDecoder` tiles. Sharpness stops at the cached width (screen x 1.5); beyond that the level-1 bitmap is scaled up (a little soft at 3-5x). Reason: WebP region decoding is not safe on API 24-25 and tiles need a second cache. Decide in Part 3 / 4 whether to add a live region render for deep zoom.
- **Not done / to check after the APK builds:** compile errors (never compiled); smooth fling on a 300-page PDF; memory on a 1.5x cache with 5x zoom; edge glow direction at the bottom; rotation while zoomed; the pill is drawn at the bottom centre (the fast scroller of Part 3 may want it elsewhere). The test the plan asks for (a folder of fake `p0001.webp` + `meta.json` v3 with `pw` / `ph`) was not run: no Android SDK in the sandbox.

### 19.3c Part 3 as built (`PdfViewerActivity.kt`, small hooks in `PdfPagesView.kt` / `core/PdfPageCache.kt`)
- **Rule**: a PDF with a cache folder (`pcDir`: >= 10 MB, not an Office conversion) is shown by `PdfPagesView` (`pv`, `pvMode`); `zf` / `rv` are hidden (GONE) and never laid out. Smaller PDFs and Office conversions keep the old RecyclerView route unchanged (no cache for them; Part 4 may decide a lower threshold).
- **Cache first**: `showFromCache` (finished cache, before the PDF opens) -> `enterPv`. **No cache yet**: `openDoc` -> `attach` -> `onDocReady` -> `enterPv` (placeholders; `Listener.onPage` -> `pv.pageReady`, `onFinished` -> `pv.refreshInfo` + `syncInfo`). `scanSizes` is skipped in this mode (sizes come from `meta.json` via `syncInfo`). `PdfRenderer` still opens in the background but only for print / save pages / OCR / live fallback; it is not used for display.
- **Wiring**: tap = `toggleUi` (or Retry when the page is in `bl`); fast scroller follows through new `PdfPagesView.onScrolled`, drag = `pv.scrollFraction`; `goTo` / Go-to-page = `pv.scrollToPage`; title/subtitle follow `onPageChanged`; the viewer's own pill is not used (the view draws its page pill); `pv.topPad` keeps page 1 below the title bar (new, set from the insets). Overview grid reads `readThumb` first, live render only when no thumbnail exists.
- **Retry**: `PdfPageCache.Info.bl` (new) -> `pv.setBlocked`; tap on such a page -> `PdfPageCache.clearBlocked` (new; drops it from `bl`, `complete=false`) + `attach` again. Works only after the PDF file is known (`file`); same renderer limits as before (a page the framework renders white can fail again until Part 4's isolated process).
- **Not done**: night mode does not apply to `pv` (pages stay light); deep zoom beyond 1.5 x screen width is soft; old RecyclerView holder code is still there for small PDFs (remove when Part 4 sets the threshold); never compiled / device-tested.
- **Check**: open a >= 10 MB PDF twice (first: placeholders then pages land, scroller + page jump work; second: all pages at once); pinch / double-tap; rotate; overview grid thumbnails; Print / Save pages / T (OCR) still work; tap a failed page = retry; a 2 MB PDF still opens in the old viewer.

### 19.3d Part 4a as built (isolated build process)
- **Files**: new `core/PdfBuilder.kt` (the old `PdfPageCache.build` / `renderPage` / `sizeFor` / `isBlank` / `pickNext`, moved; reports through `PdfBuilder.Sink`, knows no Job / viewer), new `PdfBuildService.kt` (`PdfBuildService` + `PdfBuildClient` + message codes `PB`), `PdfPageCache` (`enqueue` now runs `PdfBuildClient(...).runBlocking()` on the same single-thread queue; new `addBlocked`, `focusOf`, `fireOnPage`, `fireOnFinished`; `readMeta` / `writeMeta` are `internal`; `isBlank` delegates), `AndroidManifest.xml` (`<service .PdfBuildService android:process=":pdfbuild">`), `App.kt` (returns early in the `:pdfbuild` process: no ClipSync / FileInfo).
- **Flow**: client binds the service and sends START (pdf, dir, cw, maxW, maxPx, focus); the service builds on its own thread and sends TOTAL / CUR (page about to render) / PAGE / DONE / ERR. The client mirrors them into the `Job` (notification, progress, cancel) and fires the page listeners (now on the main thread; the viewer already used `ui.post`). `PdfPageCache.focus` is forwarded to the running client; cancel is polled every 600 ms and sent as CANCEL.
- **Crash handling**: service process dies -> `onServiceDisconnected` / `onBindingDied` -> client remembers the page that was rendering (`CUR`), restarts after 0.7 s (pages already on disk are kept); a page that was current in 2 crashes is added to `meta.json` `bl` by `addBlocked` (the builder skips pages in `bl`; Retry in the viewer clears them); 6 restarts in a row without a new page = job error "The PDF renderer keeps crashing on this file". If the service cannot be bound at all the build runs in the app process (old behaviour, no isolation).
- **Behaviour changes**: the builder no longer throttles while a viewer renders live (different process, no shared PDFium lock; `PdfPageCache.viewers` / `lastUse` / `pdfLock` are still used by the viewer and kept). `bl` pages written at the end now include pages skipped from an earlier `bl`.
- **Not done (4b)**: auto-resume after the APP process dies, settings, cache management. **Never compiled, never run on a device.**
- **Check**: open a 10 MB+ PDF: notification "Caching PDF" as before; `adb shell ps | grep pdfbuild` shows the second process while building; `adb shell am kill` / `kill` that process mid-build: the build restarts by itself and the job finishes; the app and viewer stay alive; Cancel in the notification stops the build; a PDF with a page that crashes PDFium ends with that page in "could not be drawn" and all others cached.

### 19.3e Part 4b as built (management)
- **Settings** (Settings > Search > "PDF page cache", `openPdfCache` in ui.html; `GET/POST /api/pdfcache`, ops `min` / `quality` / `cap` / `clear`): "Cache PDFs from" 5 / 10 / 20 / 50 MB / every PDF (`Cfg.pdfMinMb`, 0 = all; `PdfPageCache.minBytes()` replaces `MIN_BYTES` in the viewer and in `attach` / `lookup`; `MIN_BYTES` stays as the default only); "Picture quality" 60 / 70 / 78 / 85 / 92 (`Cfg.pdfQuality`; read in the app process by `PdfBuildClient` and sent as `q`, because `:pdfbuild` has no settings; only pages made from now on); "Size limit" 512 MB / 1 / 2 / 4 GB / none (`Cfg.pdfCapMb`, default 2 GB); "Clear all caches"; "Used space" line (next to PDFs / inside app / count / building).
- **Cache folders next to PDFs** are listed in `filesDir/pdfcache_dirs.json` (registered in `chooseDir`; missing ones are dropped when read). Size, clear and the cap use it. LRU = folder `lastModified` (touched on every open); `trimGroup` runs for the private folder (as before, now with the setting) and for the registered group after each build and on register; folders being built / in use are never removed.
- **Delete / rename / move of the PDF**: `LocalFs.remove` and `Bin.trash` call `PdfPageCache.onPdfRemoved` (cache folder deleted, empty `cache/` removed); `LocalFs.rename` / `move` call `onPdfMoved` (cache folder renamed to the new name / new `cache/` folder; the signature size:mtime stays valid; on failure it is deleted and rebuilt on the next open). Deleting a whole folder removes its caches with it. Not covered: changes made by other apps / the PC side outside `LocalFs`.
- **Auto-resume**: `enqueue` writes the build into `filesDir/pdfpending.json` (pdf path, name, cw, maxW, maxPx) and removes it in `finally` (finished, error or user cancel). When the APP process dies the entry stays; `App.onCreate` starts a daemon thread that waits 4 s and calls `PdfPageCache.resumePending` (skips entries whose PDF or folder is gone or whose cache is complete). A downloaded copy of a remote PDF in the viewer cache may be gone: then the entry is dropped. `startForegroundService` from a background start can be refused on Android 12+ (caught): the job still runs, only the notification may be missing.
- **Decisions**: the old RecyclerView holder code was NOT removed (still used for PDFs below the threshold, Office conversions and when no cache folder can be made); with "every PDF" even small PDFs use `PdfPagesView`. Chapter 19 was NOT merged into the main chapters (kept as the record; merge when the feature is device-tested).
- **Check**: set "Cache PDFs from" to Every PDF, open a 1 MB PDF: it uses the new viewer and has a `cache/` folder; Settings shows size and count; Clear all empties them (a building one stays); rename the PDF in LANShare: the cache folder is renamed and the PDF reopens instantly; delete it (and via the recycle bin): the folder is gone; set the limit to 512 MB, open several big PDFs: the oldest cache folders disappear; start a big build, swipe the app away (force stop) and start it again: after ~4 s the notification "Caching PDF" is back and the build continues; quality 60 vs 92 gives visibly different page file sizes for new PDFs.
