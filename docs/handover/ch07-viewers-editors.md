## 7. Viewers and editors (video, image, PDF, text)

All are plain `Activity` classes (no AppCompat, no Compose), hand-built views, `JobOverlay.install(this)` after `setContentView`. They only accept `http://127.0.0.1` / `localhost` URLs (the local server's `/api/dl`, which does Range requests, so local / peer / SMB files stream without downloading). Handover of a list to a viewer goes through a static `pending` object (no Binder size limit). **Not compiled / not device-tested in the notes** (see section 2).

### 7.1 Video player (`PlayerActivity.kt`, `PlayerWidgets.kt`)
- Media3 / ExoPlayer 1.3.1 (`media3-exoplayer`, `media3-ui`). Tapping a video calls `LSAndroid.play(json)` (`MainActivity.Bridge.play`) with the folder's videos as a playlist: `{start, items:[{name, url, key, subs:[{name, url}]}]}`. Browsers (no `LSAndroid.play`) keep the HTML5 viewer (`openMedia`); inside it a play button / the error box offer "Play in player".
- MKV / AVI / MOV / WebM / MP4 / FLV / MPEG, audio + subtitle track menus, speed, next / previous, resume position (SharedPreferences `ls_player`, key `dev|path|size`), **PiP** (Home while playing, or the button), double-tap +-10 s, swipe left = brightness / right = volume, Fit / Zoom / Stretch, rotate, auto landscape for wide videos. **Pinch zoom (2026-11-12, NOT compiled):** `ScaleGestureDetector` in `setupGestures`; `zoom` (1..`MAX_ZOOM` 8) / `panX` / `panY` / `baseS` applied in `applyZoom()` on top of the turn + fit scale (`setXform`); zoomed: one finger pans (brightness / volume swipe off), double tap = reset; zoom resets on turn, next video, PiP. Turn left / right buttons are in `row2` again (7 buttons, size `/ 7` in `layoutBars`).
- Sidecar subtitles (same base name, `.srt .vtt .ass .ssa`) fetched, converted to UTF-8 (windows-1254 fallback) into `cache/subs` and attached.
- Manifest: `PlayerActivity` is its own task (`singleTask`, empty affinity) so PiP works; theme `Theme.LANShare.Player`. No background-audio service (audio stops when the screen is off / PiP closed). `PlayerWidgets.kt`: colours (light = white page, dark = black) and canvas-drawn icons (no drawable resources or font glyphs).

### 7.2 Image viewer (`ImageViewerActivity.kt`, `androidx.viewpager2`)
- `LSAndroid.viewImages(json)` = `{start, items:[{name, url, size}]}` in the current sort order. Each picture is fetched from `/api/dl` into `cache/img/<n>.bin`, decoded with `inSampleSize` (longest side <= 3072 / 4096 px by memory class, never above the 4096 GPU limit), EXIF-rotated, kept in an LruCache with the neighbours preloaded. `ZoomImageView` (`ScaleType.MATRIX`): pinch, double-tap (fit <-> 2.5x), pan, at the edge of a zoomed picture the drag becomes a page swipe. Tap hides the bars. `.gif` / `.svg` (and `.heic` below Android 9, `LSAndroid.sdk()`) go to the HTML viewer. Originals above ~4096 px are not shown at full pixel resolution.
- **Top bar redesign (2026-10-10)**: two lines - middle-ellipsized file name + `date · time`; position in a pill at the bottom centre (`countPill`); drawn Material icon buttons (`IconBtn`, 44 dp): text layer (T), edit, share, and a **⋮ menu** (Slideshow / Stop slideshow, **Details**: name, modified, pixels, size, position). Slideshow 4 s, stops on manual swipe.
- Text layer / OCR: see 11.2. Viewer also reads `OcrPrefs` and has `AutoOcr`.

### 7.3 Image edit (`ImageEditActivity.kt`, 2026-10-08)
Pencil button in the viewer: rotate left / right, drag-to-crop, resize by px or 100 / 75 / 50 / 25 %. Preview is a 2048 px bitmap; on Save the operations are applied once to the original at full resolution (`ImgEdit.render`: EXIF orientation -> rotation -> crop -> scale, one Canvas pass). Save as copy (`name (edited).ext` next to the original; for peers / SMB / archive entries into `Pictures/LANShare Edited`) or replace the original (this phone, jpg / png / webp only); the viewer reloads the page after a replace and drops the page's OCR cache.

### 7.4 PDF viewer (`PdfViewerActivity.kt`)
- Built on `PdfRenderer` (so: no document search, no in-page selection, no links, and **no streaming** - it needs the whole file).
- **Viewer 1 (2026-10-10)**: fast scroller (`PdfScrollBar`, right edge, bubble `page / total`); page **overview grid** (▦, 3 columns, 5 from 600 dp; thumbnails 260 px on the `pdf-render` thread, 12 MB cache); **page text** (T): renders the current page up to 2400 px and reads it with OCR into a selectable dialog with Copy / Share (works for scans; OCR, not the PDF's own text).
- **Viewer 2 (2026-10-10)**: after scrolling stops the next two and previous page are pre-rendered (`prefetch`, `ahead` set; a page with no picture first gets a quick 1/3-size render); in the overview, long-press selects pages (tap toggles, All / clear), bottom bar **Print** (all pages when none selected), **Save PDF** (to Downloads, `name (p. 3-5).pdf`, MediaStore on API 29+), **Share**. Print uses the system print dialog (`PrintDocumentAdapter`): the whole document goes as the original file; selected pages / a range are rebuilt by `JpegPdfWriter` (one JPEG per page at ~180 dpi, one bitmap in memory; text in such copies is not searchable). **Big files**: from other devices / SMB, kept in `cache/pdfc` for 12 h (400 MB cap, oldest first; same key + size = same file, so a same-size edit shows stale up to 12 h), interrupted downloads resume with a Range request (3 tries); local files read fresh.
- **Page cache (2026-11-04, not compiled / not device-tested)** - `core/PdfPageCache.kt` + small hooks in `PdfViewerActivity.kt`.
  - *Rule*: PDF >= `MIN_BYTES` (10 MB), not an Office conversion (`officeSrc != null`). `openDoc` (worker thread, after the first `PdfRenderer` opened) calls `PdfPageCache.attach(...)`; it returns the cache folder `pcDir` (@Volatile) or null.
  - *Where*: PDF on this phone -> `<pdf folder>/cache/<name without .pdf>/` with `.nomedia`, `meta.json`, `p0001.jpg ...` (JPEG q90, width = min(screen width, `maxW`), same GPU / `maxPx` limits as `renderSize`). Folder not writable (read-only USB / share) or PDF from SMB / other device (downloaded copy) -> `filesDir/pdfpages/<hash>/`, total capped at 2 GB (oldest folder first).
  - *Validity*: `meta.json` has `sig` (local: `length:lastModified`; remote: the viewer `key` = dev|path|size), `cw`, `n`, `complete`. Changed `sig` -> pages and meta deleted, rebuilt. Pages are written as `.tmp` then renamed, so a half page is never read; a rebuild skips pages already there (resume on next open). `complete` stays false when any page failed (it is retried next open).
  - *Reading*: `renderPage(pos, w, h)` first calls `PdfPageCache.read(pcDir, ...)`: decodes the JPEG (inSampleSize + exact scale down). Returns null when the viewer wants more pixels than cached (zoom, `w > cw + 2`) -> normal live render. Pages not yet cached render live as before.
  - *Background build*: one daemon thread (`pdf-cache`, single executor, one PDF at a time), own `PdfRenderer` + file descriptor on the PDF (independent of the viewer; a trimmed download copy stays readable while open), `THREAD_PRIORITY_BACKGROUND`, `PARTIAL_WAKE_LOCK` (3 h timeout), free-space guard (n x 450 KB + 50 MB). Registered as a `Job` in `Jobs.all` (id `pc<hash>`, `bytes=false`, `total` = page count, label "Caching PDF: name i/n"), so `LanShareService` (foreground, `dataSync`) shows it in the notification and `JobView` / `JobOverlay` give progress + cancel (`job.cancel` is checked per page). `enqueue` also calls `startForegroundService(LanShareService)` (caught if refused). `PdfPageCache.viewers` (inc in `onCreate`, dec in `onDestroy`) makes the builder sleep 40 ms per page while a viewer is open. The build survives closing the viewer / swiping the app away (service is not `stopWithTask`); the notification Stop button or a system kill ends it, and it resumes on the next open (no automatic restart after a process kill).
  - *Also changed*: a PDF on this phone (`key` = `local|<virtual path>|<size>`) is now opened in place via `Core.local.real(path)` (`realSrc`) instead of being copied through the loopback `/api/dl` into `cache/pdf/doc.pdf`; falls back to the old copy when the path does not resolve (e.g. inside an archive) or is unreadable. This supersedes "local files read fresh" above (they are still read fresh - just from the original).
  - *Format changed 2026-11-04 (chapter 19, Part 1)*: pages are now WebP (`p0001.webp`) + thumbnails (`t0001.webp`), cache v3; everything above about JPEG / q90 / 450 KB is superseded by 19.3.
  - *Not done*: no "clear cache" button, deleting / renaming a PDF in the app does not remove its `cache/<name>` folder, no settings switch for the 10 MB threshold, no automatic restart of an interrupted build without opening the PDF, no cache-first open (the PDF is still opened with `PdfRenderer` first; for remote PDFs it is still downloaded first).
  - *Check on device*: open a >= 10 MB local PDF -> notification shows "Caching PDF" with progress -> close the app -> it keeps going -> `cache/<name>/` exists next to the PDF -> reopen: all pages appear at once, zoom still sharp; replace the PDF -> cache rebuilds; open a read-only / SMB PDF -> pages land in the app's private folder.

### 7.5 Text editor (`TextEditorActivity.kt`, `CodeHl.kt`, `MdRender.kt`)
**No handover existed for these.** What the code headers say: `CodeHl` = small dependency-free syntax highlighter (`scan` returns packed triples start / end / kind); `MdRender` = light Markdown -> blocks for the editor's preview (headings with slugs / outline, bold / italic / strike, `code`, nested bullet / numbered / task lists, nested quotes, rules, links incl. `#anchor` and reference links, front matter, simple HTML; no library, no WebView). Images are only tappable labels (no loading); relative links to other files are not opened. The old docx branch of `TextEditorActivity` (`DOCX_MAX`, read-only banner) was meant to be removed when Word files moved to the Office viewer (`docx` is no longer in `ED_MORE`); `core/DocxText.kt` is still in the repo and unused (15.2). `ED_MORE` (ui.html) is the editable-extension list.
