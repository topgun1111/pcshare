## 6. UI layer (ui.html, native list, main menu, gallery)

### 6.1 How the UI is built
- `assets/ui.html` owns screens and logic (single page, ~470 KB, ~224 DOM nodes at rest, ~10 MB JS heap, main script runs in 31-53 ms). `MainActivity.Bridge` (`LSAndroid.*`) is the JS <-> Kotlin interface; `onNewIntent` -> `handleShare` handles share intents (`ACTION_SEND`, `ACTION_SEND_MULTIPLE`).
- **Twin rule**: whatever Kotlin paints natively (list rows, path bar, chrome, drawer, search row) has an unchanged HTML twin underneath. The twin is the fallback and the source of truth for taps: native taps come back as `nlOn(...)` / `nlCh(...)` / `nlDr(...)` and click the same HTML element. Row builders exist twice (`NlModel.rows` in Kotlin, `nlBuild` in ui.html) and their `sig` (signature) must stay equal or rows flicker - when you add a row field, change **both** and include it in `sig`.
- **Holes**: the native list is a RecyclerView over the WebView; it lets drawing and touches through only for the rects `nlLay()` reports (`#fab #toast #dlw`, open sheets, `#jb`, `#jp`). A new floating element must be added there. Overlays that hide the native list / chrome / search / swipe (`#gal`, `#pv`, `#home`) are in the same lists (`nlLay`, search push, `nlChPush`, swipe `blocked`).
- Theme: page tokens `--sel --cont --ac ...`; `AppPal.kt` mirrors the page palette (from `nlPalette()`) in memory + SharedPreferences so native screens (Storage Analyzer) use the app's theme. `nlTheme()` (theme picker + system listener) re-pushes palette, chrome, search and layout (a theme change used to leave the list half-themed; `NlHeadView.pal` setter now sets `dirty`).
- Testing UI-only changes: `node --check` of the extracted JS, Chromium with mocked `api()`; `chrome://inspect` on the device.

**Look decisions (all native + page twin)**
- **Classic folder** (paper-sheet icon) in every view: `NlClassicFolder` (100 x 87.7 unit box) used by `NlGridView.folder` and `NlRowView`; page twin `FOLD` (viewBox 100x88); `#list.v-grid .fold svg` 100 % wide.
- **Grid cards**: no date line (count / size only), folder icon 62 % of the card square; the category badge (DCIM, Download, Music...) is drawn INSIDE the folder icon (centre of the front panel); with a badge the folder grows to >= 62 dp (max 94 % of the card) so a 24 dp badge fits.
- **Narrow rows** (split screen): second line (count left, date right) - date loses its time, then ellipsizes, then hides; compact view caps the right text at 45 %.
- **New folder button hid the last files**: `NativeList.ensureMgr` gives the RecyclerView 88 dp extra bottom padding (`clipToPadding = false`, list and grid); page fallback `#list::after` spacer 88 px + safe area.
- Row divider 2 px (CSS `.row` border-bottom + `NativeList` divider); top bar 52 px with 48 px buttons and 30 px icons (`.bar .ibtn`, `NlChrome` `NlBarView`); hamburger drawn 32 dp (touch target 40 dp); drawer "Main menu" row bigger (`.di.mm`: icon 44, title 23 px, subtitle 15 px, row 76 px).
- **Text size fix**: natively painted text (`NativeList`, `NlHead`, `NlDrawer`, `NlChrome`) multiplies `UiScale.tf` (set in `UiScale.wrap` / `save`), so Settings > Text size works on phones that show the native list. Row heights are fixed: text at 150-160 % may clip.
- **Previews in the list**: PDFs show their first page with a small "PDF" pill (`Thumbs.make` renders `.pdf` with `PdfRenderer`: page 1, 480 px wide on white, a tall page cut to its top square, JPEG 75, same disk cache, one at a time via `pdfLock`; password-protected / broken PDFs keep the icon; rows get a `path` for local PDFs 1 B - 60 MB in BOTH row builders; `/api/thumb` answers PDFs; not for other devices / SMB / archives). Office files: embedded preview image (8.5). Subfolder-search hits ("In subfolders (n)", `nlBuild` branch `i._h`) send `p`, `s`, `t` for pictures, videos and local PDFs so they get thumbnails; hits stay non-selectable and tapping one goes to its folder.
- **Pull to refresh**: file browser (native `SwipeRefreshLayout` / page `#ptr`); Gallery / Videos album home (`galForce()` zeroes `GALT` and re-reads `/api/albums`, because album lists are cached 15 s); inside an album (`pullBind(sc, box, go, ok)`, 70 px threshold, not while items are selected).
- **Select-all** toggles (second tap with everything selected unselects) in Gallery / Videos albums (`galView`), AI-search results (`isView`) and the file browser (`#allsel`).
- **Edge swipe** (`MainActivity.dispatchTouchEvent`): swipe right from anywhere below the header (edge 40 dp, rest of the screen 72 dp and mostly horizontal; starting in the header = path / device chips scroll) toggles the **Main menu** (`lsEdgeOk()` + header bottom reported to Kotlin every 200 ms via `LSAndroid.edgeOk(ok, top, vw)`; ui.html `lsEdgeOpen()` -> `homeShow()` / `homeHide()` + `nlLay(true)`); ignored when a dialog / sheet / viewer / selection / search is open. A 32 x 200 dp left-edge strip is excluded from the system Back gesture (Android 10+). The old "swipe right = previous device" is gone (swipe left = next device stays).

### 6.3 Main menu (home screen, "Start menu")
**Status**: Material 3 look implemented as a `#home` overlay in ui.html (not compiled in the notes; JS `node --check` only).
- **Design history**: first approved design = grid of big rounded icon tiles (design artifact `https://claude.ai/artifact/VsN5t5zJd7xkHJmvMj7kT7`, source once in the zip as `design/HomeMenu.dc.html`); replaced on 2026-10-10 by **Material 3**: storage card on top (live used / free from `/api/space`, fallback `ls_used`), then sections **Browse** (Gallery -> `/Pictures`, Videos -> `/Movies`, Downloads -> `/Download`) and **Network and tools** (Printers, SMB Shares, Storage Analyzer disabled at first; later replaced by **Favorite folders**, and a **Devices** tile was added - their exact section is not recorded). Tiles use theme tokens (`--sel --cont --ac`) + per-tile `--hc1..7`; dark theme has own `--hm*` vars; icon paths in `HM_P` (`HM_P.sto` kept for a Storage Analyzer tile that was removed 2026-10-11).
- **Tiles**: Gallery / Videos / Downloads show "size (files)" (`GET /api/folderstat`; last value from `localStorage` `ls_hs2_<path>` shown at once, refreshed when the phone has counted; cache key was renamed from `ls_hs_` so the old thumbnail-inflated number is not shown). **Network and tools row (since 2026-10-28)**: SMB Shares -> `openSmb()`, **FTP servers** / **Cloud servers** -> `srvPicker('FTP' | 'Drive')` (saved servers listed here only, not in Devices). The old Printers and Favorite folders tiles are gone (Printers: `pickPrinter(..., busy)` still reachable from the drawer). **Devices** (`HM_P.dev`, subtitle = number of other devices, `hmDevSub()`) -> `devPicker(true)` bottom sheet (This device + all peers, "Add by IP" row replaces the "+ IP" chip). The **Favorite folders** tile (cascading popup `hmFavMenu`) was removed 2026-10-28; Quick folders live in the drawer. Opening the menu triggers `/api/scan` + `pollPeers()`.
- **Behaviour**: shown only on a **fresh launch** (`MainActivity.showHome` = `b == null` and the intent has no SEND / VIEW / PRINT action, read by `Bridge.homeStart()`), never on a share intent. `openLoc` / `openDev` call `homeHide()`. `lsBack`: home is the bottom of the stack (Back there leaves the app); Back at the root of main storage returns to home. The three-dot button opens Settings (there is no overflow menu). The drawer's first row is "Main menu"; the drawer tab strip (Folders / Favorites / Recent) and the old Favorites / Recent-history features were removed 2026-10-11 (`#dtabs` stays in the DOM, `display:none`, `NlDrawer` hides its tab view). Pictures in Quick folders is no longer permanent (removable, not re-added at start; reset to default brings it back).
- Other related edits: the grey "x free of y" line above the root crumb is hidden (`#free{display:none}`); the devices chip bar `#peers` is hidden (`renderPeers` still builds it); the disk-percentage **pill** (`#used` / `NlHead` pressKind 4 -> `nlOn('used')`) now calls `pillTap()` = Storage Analyzer (12) with fallback `spaceInfo()` (usage bar + this folder's counts).
- **Checklist**: launch -> menu shows its tiles; each tile opens its screen and Back returns to the menu; share a file into the app -> send dialog (no menu); rotate / small text size / dark theme -> tiles fit (`UiScale`); the edge swipe toggles menu <-> folder.
- Open: "every start vs fresh launch only" unanswered; maybe a Settings switch "Start with: Home / last folder"; live subtitles, long-press to reorder / hide tiles, more tiles (Documents, Apps, New files, Recent, Remote, Trash like *File Manager +*).

### 6.4 Gallery (Pictures / Videos)
- Album cards are page-rendered (`.albums`, `mkAlbum` / `mkAlbumX`, `galFetch`). A card opens **`galView(a)`** (`#gal` overlay): that album's pictures + videos as one square-thumbnail grid (newest first, chunked); Back closes (`lsBack`, `o._sel`). `GCX` (+ `cxd / cxp / cxl`) makes `nativeImg`, `nativePlay`, `mediaList`, `openMedia` read the album instead of `S.dev/S.path/shown()`. `#gal` hides the native chrome like `#pv`.
- **Hold menu**: press-and-hold selects like the file browser (selection `GS` local to the album); bottom bar `#gal .gb`: Copy, **Move** (`galPick(a)` sheet lists the other albums of the same kind + "New album" -> clip(cut) + `/api/paste`), Share (any number of files; `LSAndroid.shareFiles({items:[{name,url,size}]})` -> `MainActivity.shareFilesImpl` fetches into `cache/open` with one cancellable progress notification, then `shareFileList` opens the chooser via FileProvider), Print (`doPrint(preset, cx)` takes an explicit `{items,path,done}` context; hidden for video albums), Details (`doDetails(it, pth)`), Delete (-> Recycle bin). Selected thumbnails shrink into a rounded tile with an accent check; rounded floating bar, slide animations (CSS `#gal .gb`, `.gh.sl`, `.gc.sel`).
- **Copy/Move if new (2026-10-22)**: bar button **Copy/Move new** -> Move or Copy -> pick album -> `Jobs` conflict mode `unsim`: every file is compared with the pictures already in the target folder (`DupFinder.SimIndex.match`: same shape + difference hash <= 20 of 256 bits = same picture in another name / size / quality; videos and undecodable files only when byte-identical). Match = skipped, original stays (also for Move); no match + same name = renamed `name (1)`; new folders are renamed in one step on the same volume, otherwise copy + delete. Result note: `N moved/copied, S skipped`. Moving a folder: files that were copied are removed from the source one by one, skipped look-alikes stay (the folder is removed only when nothing was skipped). Same check in the paste conflict card (**Only if not similar**) and in **Merge > Skip look-alikes**. Limits: first run in a big target decodes every target picture once (slow, cached per job); videos are not compared visually. **Test**: album A has `IMG_1.jpg`, album B has a resized copy named `x.jpg` + a different `IMG_1.jpg`: Move A->B skips the pair, renames the other; cancel mid-way; Copy keeps originals; Merge with Skip look-alikes leaves look-alikes in their album.
- **Per-file ask card: Only if not similar (2026-10-22)**: the "Already exists - replace?" card (copy / move / paste / merge, this phone only) has a 5th button; answer `unsim` / `unsim_all` ("all remaining" = sticky): look-alike (`DupFinder.look`) -> skipped, different picture -> kept as `name (1)`. `Jobs.work` + `AlbumMerge.work`; UI `lvAsk` button list in `ui.html`.
- **Small albums hidden** by default (<= 1 item, Android resource folders `mipmap-*`, `drawable-*`; `galJunk`, key `ls_galhide`; button under the albums toggles).
- **View pane in the Gallery**: only **Albums: 2 / 3 / 4 columns** (`NlSheets.kt` `St.gal`; `S.cols`; saved with view / sort in `ls_g` / `ls_pf` so "Apply to all folders" works; the page also sends `gc: S.cols` in the layout JSON). Album covers are 4:3 (`.alb .acv`, `object-fit: cover`, centred 50 % / 35 %); thumbnails themselves keep the aspect ratio.
- **AI search entries**: press and hold an album of /Pictures -> bottom-bar **AI search** (`albHold`; hidden for video albums) -> `isView(sdir, sname)` limited to that folder; albums that are NOT direct folders of /Pictures (DCIM/Camera, WhatsApp..., `mkAlbumX`) open a popup "Search the pictures in this album with AI?".
- **Hide** (2026-10-11): hold a file / folder on this phone -> **Hide** (not in the Gallery album home, which has its own). Hidden paths share the list of hidden albums (`HGAL` / `ls_galhid`, saved by `hgSave()`); **Settings > Gallery settings > Hidden albums, files and folders** lists them with Unhide / Unhide all; filtered like dot-files (`vis()`, search hits via `hidP` / `hidAnc`), come back with **Show hidden files**; native side via bridge `nlHidden(json)` -> `NativeList.setHidden` / `NlModel.hidden`. Files are not renamed. Side effect: albums hidden before are now also hidden inside plain folders. This phone only.

### 6.4a Other phones' gallery (read-only, 2026-10-23; merged from `HANDOVER_GALLERY.md`)
**Goal.** On the local Gallery / Videos main page, *Other phones* lists the other LANShare phones; opening one shows THAT phone's gallery like the local one (album cards, covers, counts, grid, viewers). View, open, copy to this phone, AI search and print; no move / hide / delete / merge. Not run on a device (JS checked with `node --check`; Kotlin built by CI only).
- **Backend (`core/Routes.kt`)**: peer routes `/p/albums?kind=vid|img` (`Albums.json` of that phone), `/p/thumb?path=&big=1`, `/p/vthumb?path=` (video JPEG + `X-Duration`), `/p/imgsearch?mode=status|visual|text&q=&whole=&dir=` (search runs ON the remote phone with its own index and model). Local UI routes `/api/ralbums?dev=[&kind=vid]` (404 text "Update LANShare on <name>" for an old build), `/api/rthumb?dev=&path=[&big=1][&video=1]` (falls back to `RemoteThumbs.make` for old builds), `/api/rimgs?dev=&mode=...` (forwards, 90 s timeout), helper `remotePhone(dev)`. Album / cover paths are relative to that phone's storage root, the same virtual paths `/api/ls`, `/api/dl`, `/api/file?dev=<id>` use. Both phones need the new build for fast thumbs and albums.
- **Albums UI (`ui.html`)**: `galRoot()` is device independent (`/@gallery`, `/@videos` on ANY dev); `galFetch()` caches per kind AND dev (`GALPK='img|<dev>'`, `GALA.dev`, `GALE`); `mkAlbumR(a)` = remote album card (read-only); `galPhoneBar()` chip *Other phones* / *<phone name>* -> `galPhones()` sheet (This phone + online / offline `kind==='LANShare'` peers); remote also gets a Photos / Videos chip. Hidden-albums (`ls_galhid`) do not apply to remote albums; *Hide small albums* is shared.
- **Inside a remote album**: `galView(a)` takes `a.dev` (`D`, `rem`); list = `/api/ls?dev=D`, `GCX.dev=D` so image / video viewers stream `/api/dl?dev=D`; thumbs via `/api/rthumb` (no duration badge on remote videos). Selection bar: *To this phone* (album picker -> clip copy from D -> `/api/paste` local; `galForceLocal()` drops the album cache afterwards), Copy, Share, Details, **Print**.
- **AI search**: `risView(D,dn,sdir,sname)` in the `#gal` overlay: Visual / Text in pictures tabs, Whole word / Contains, status card (that phone has no model / no scan yet, old build -> its 404). Entry: chip *Search* in `galPhoneBar()` (remote Photos home = whole phone) and the search icon in a remote album header. Scanning / model download is done on the other phone; videos are not searched.
- **Print**: button in the remote selection bar (photos only) and in `risView` results -> `doPrint(null,{items,dev:D,...})`; no backend change (`Jobs.startPrint` / `PdfPrint` / `WifiPrint` read files through `Jobs.ep(srcId)` = `RemoteFs`); history `phAdd` stores `dev:D` so re-print works.
- **Open ideas**: duration badge for remote videos, per-dev hidden albums. Device check: albums list, album grid, viewer for photo and video, copy to this phone, search (visual and text), print (this phone, Wi-Fi, PC, PDF, sheet layout).

- **PC pictures gallery (2026-10-27, NOT compiled / run)**: each saved SMB share (a PC) is listed in the *Other phones* sheet under "PC". Opening it shows ONLY the PC's Pictures folder and its sub-folders as album cards (photos only: no Videos chip, no AI search). `core/PcPictures.kt`: `find()` looks for Pictures / Resimler / Bilder ... (a share that is the folder, `<share>/Pictures`, `<share>/Users/<name>/Pictures`; Public / Default skipped; newest wins), `albums()` walks it with `lsFast` (2500 folders / 100 s, cached 90 s; one album per folder that holds pictures; junk folders skipped), `setDir()` stores `picdir` in the share (kept by `Smb.update`). Routes: `/api/ralbums?dev=smb:..[&fresh=1]` (smb branch), `GET/POST /api/pcpicdir`. Thumbs = existing `/api/rthumb` fallback (`RemoteThumbs.make`, whole picture pulled once, cached). UI: `isPc()`, `galPhones()` PC rows, `galPhoneBar()` chip *Pictures folder* -> `pcPicDir()` (type a path, empty = automatic).
