## 19. Remote shell = real terminal (REMOTE_SHELL_PLAN.md, 5 parts, all coded 2026-10-30)

**Part 1 DONE (2026-10-30)** - not yet run on a real PC / phone (written and protocol-tested on Linux only).
- PC `tools/phone_explorer.py`: `TermSession` (one shell per session id), `_ConPty` (Windows ConPTY through ctypes: CreatePseudoConsole + CreateProcessW with PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE; shell = %COMSPEC% or powershell.exe -NoLogo, cwd = home), `_PosixPty` (same interface, only so the protocol can be tested on Linux). `POST /term` (form body, same password/lock as /exec, `_auth()`): `act=open sid shell cols rows` (same sid = same session, answer `existed`), `read sid o wait<=25` -> `{data(base64 raw bytes), from, o, alive, code, reset}` (offset based, same o = same bytes; buffer 4 MB, `reset` when the phone is behind it), `in sid seq data(base64)` (seq counts up, `seq <= last` is ignored = never typed twice), `resize`, `close`. Max 3 sessions, idle 30 min closes, PC kept awake while a session lives. `/exec?probe=1` now also returns `term:1`.
- Phone: `PePc.term()` (3 tries, new socket each; 404 "not found" = old PC program), Routes `pcterm` (JSON body -> form), Routes `/xterm/<file>` serves assets/xterm/{xterm.js, xterm.css, xterm-addon-fit.js} (xterm 5.3.0 + fit 0.8.0, loaded by ui.html only when the screen opens).
- ui.html `openRemoteShell`: xterm terminal, `start()` (open or re-attach; `RSH_S` {ip,port,sid,sh,seq} survives closing the screen), `loop()` long-poll read with retry on network errors, `flush()` numbered input, key row (Esc Tab Ctrl arrows ^C; Ctrl sticky), cmd/PS switch (closes the old shell). The old Run / text box / history UI and the use of /exec from this screen are gone (PC side /exec stays for old apps).
- NOT done / to check on the devices: (1) Android keyboard (word suggestions) inside xterm - the plan's biggest unknown; (2) ConPTY on a real Windows 10/11 (never run); (3) the PC program is run as `python tools/phone_explorer.py` (exe build was removed), APK by CI; (4) no fallback "old simple mode" for Windows older than 1809 (the screen shows the PC's error).
**Part 2 DONE (2026-10-30)** - `ui.html` only (`openRemoteShell`, block "part 2: select / copy / paste / clear"); PC program, Kotlin, assets untouched. NOT run on a device (JS syntax-checked with `node --check` only). The plan is `REMOTE_SHELL_PLAN.md` (repo root; not in the part 1 zip).
- **Selection mode:** long-press (450 ms, < 10 px movement) on `tw` -> `selOn(cell)` selects the word; transparent layer `sl` (touch-action none) then takes touches: tap = word, drag = range (anchor cell fixed, `setRange`), edge within 28 px of top / bottom scrolls 1 line / 80 ms. Two round handles `hS` / `hE` (drag one end; finger offset: cell above-left / above-right of the finger); `placeH()` repositions on select and `xt.onScroll`. Cells: `.xterm-screen` rect / cols / rows, rows are absolute buffer rows (`viewportY` + row), selection = `xt.select(col, absRow, len)`. A tap `click` after a long-press must not open the keyboard (`lpFired`).
- **Menu `mn`** (Copy, Paste, Select all, Clear, Done): Copy = `xt.getSelection()` -> `peCopy()`; Paste = `navigator.clipboard.readText()`, on refusal `askPaste()` (textarea box); `sendPaste()` refuses > 100,000 chars, asks `dlg` when the text has several lines, then `xt.paste()` (bracketed paste kept, newline -> CR) -> `onData` -> `typed()` -> numbered `in`; Select all = whole buffer; Clear = `xt.clear()` (phone side only, nothing sent to the PC).
- **Ctrl+C:** the `^C` key and a real keyboard (`attachCustomKeyEventHandler`, in `hookSel()` called from `mkTerm`) copy when `xt.hasSelection()`, else send `\x03`.
- **Backspace / Del keys** added to the key row (`\x7f`, `\x1b[3~`), hold = repeat after 400 ms every 70 ms (each repeat is a numbered `in` request: check it does not flood on a slow link; the soft keyboard's own Backspace repeat is the IME's).

**Part 3 DONE (2026-10-30)** - `ui.html` only (`openRemoteShell`, block "part 3: key row"); the old part 1 key loop is gone. NOT run on a device (`node --check` + the modifier functions run in node; Turkish round trip run on Linux).
- Row (`KEYS`): Esc Tab Ctrl Alt, arrows, Home End PgUp PgDn, `|` `\` `~` `/`, ^C, Backspace (`\x7f`), Del. `Ctrl` / `Alt` toggle `ctrl` / `alt` (buttons `cb` / `ab`, class `fill`) and are cleared by `clearMods()` after the NEXT key, whether typed on the phone keyboard (`typed` -> `mod()`) or tapped in the row (`keySeq`, `mod`). `mod()`: Ctrl + ASCII letter / `@[\]^_` = control code (ASCII only: Turkish `ı` upper-cases to `I`, so it is excluded), Alt = ESC + key. Cursor keys with modifiers send the xterm form `ESC [ 1 ; m X` / `ESC [ n ; m ~` (m = 1 + 2 Alt + 4 Ctrl). Pasting clears the modifiers.
- Held keys (arrows, PgUp, PgDn, Backspace, Del) repeat after 400 ms every 70 ms with the same bytes; a tick is skipped while 20 or more batches wait in `inq`.
- `^C` copies when text is selected, else sends `\x03` (from part 2).
- Real keyboard: xterm handles its shortcuts itself (`onData`); only Ctrl+C with a selection is intercepted (part 2). Not changed in this part.
- Turkish: typed text goes out as UTF-8 (`TextEncoder`), output is `xt.write(bytes)` (xterm keeps UTF-8 state across chunks). Checked on Linux: `TermSession.write` of `çğıöşü ÇĞİÖŞÜ` through `cmd` (= the POSIX stand-in shell) comes back unchanged in `read`. NOT checked: real ConPTY, the Android keyboard (IME composition of ç ğ ı ö ş ü inside xterm's textarea), Turkish file names in `dir`, programs that print in the OEM code page (cp857) - if they show wrong, set `chcp 65001` on open as a next step.

**Part 4 DONE (2026-10-30)** - `ui.html` (`openRemoteShell`) + one field in `tools/phone_explorer.py` (`/term` `open` reply now has `"seq": t.seq`). NOT run on a device (`node --check`, `py_compile` only).
- **Reconnect:** `loop()` (read side) no longer gives up after 150 s: backoff 1-5 s, 10 min total, title shows `stat('reconnecting…')`. It has its own counter `lg` (a read restart never cancels a key batch: `gen` is only for the session). `kick()` (document `visibilitychange` visible, window `online`) cuts the nap short and starts a fresh `loop()` (a read waiting on a dead socket is dropped, its late answer is ignored because `lg` moved on); only when `opened` (set after `open` succeeded).
- **Keys:** `flush()` keeps one numbered batch until the PC takes it (same `seq`, so the PC types it once), retries up to 150 s with `nap`, new keys queue in `inq` meanwhile. `saveSess()` stores `RSH_S` in localStorage `ls_rsh_sess` ({ip,port,sid,sh,seq}) after open and before each batch.
- **App restart:** `start()` takes the saved session when ip / port / shell match and asks the PC to `open` the same sid (`existed` = still there; the screen is replayed from offset 0, up to 4 MB). `RSH_S.seq` = max(saved, PC's `seq`); an old PC does not send `seq`, then seconds since 1970 is used (always above any earlier number). A failed `open` keeps the saved sid (PC unreachable now, try again later); it is dropped on shell ended, `terminal not found`, shell switch. Password is still asked when not remembered.
- **Big output:** `xt.write(u, cb)` is awaited before the next read (backpressure). `reset` (phone behind the 4 MB buffer) clears the screen and toasts only when something was already shown. Scroll-back is still 5000 lines (part 5: ~10,000).
