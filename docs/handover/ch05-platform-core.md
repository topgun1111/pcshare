## 5. Platform core (server, protocol, jobs, file systems)

### 5.1 Server, routes and behaviour gotchas
**Summary.** `core/*.kt` serves `assets/ui.html` from `MiniHttp` and answers the `/api/*` and `/p/*` routes (`Routes.kt`). The wire protocol equals the old Python server, so builds interoperate. The Chaquopy / Python era is gone (history in 5.12).

**Gotchas to keep in mind**
- `org.json` **drops a key** on `put(k, null)`: real nulls must be `JSONObject.NULL` (used for `used`, `storage_ok`, `error`, clipboard).
- Query parsing mimics Python `parse_qs`: `+` / `%XX` decoded, **blank values dropped**, first value wins.
- `MiniHttp` does not support chunked request bodies, `Expect: 100-continue` or `HEAD` (the Python server had none either). An error mid-upload closes the connection instead of draining the body.
- Android < 15: never call `removeFirst()/removeLast()` on a `java.util.List`; only on `kotlin.collections.ArrayDeque`.
- `storageOk` is evaluated live on every call. `File.renameTo` is used for rename / move, with copy + delete fallback across volumes (`LocalFs.move`).
- `tcpProbe`: "connection refused" = host up, try the next port; anything else = nobody home (same as Python's errno logic).
- The app's HTTP server answers **any app on the phone** at `127.0.0.1`; anything sensitive (root, 5.6) needs a per-process token.
- Port: the server tries a range (8765-8784 in the Python era); the URL is read back from `Core.url`, so any port works. `Core.url` is published at ~106 ms after process start (13).
- Config: `<filesDir>/lanshare.json` (`Cfg`). SMB passwords are stored in plain text in the app's private storage.

**Discovery** (`Discovery.kt`): UDP beacons (port 48555) + unicast sweep + TCP scan + live checks. Network changes (`ConnectivityManager` default-network callback in `LanShareService`) trigger a debounced rescan.

**Security note**: no PIN / pairing by design; use on trusted Wi-Fi. An opt-in PIN / trusted-networks toggle was never built. `MANAGE_EXTERNAL_STORAGE` is fine for sideloading, needs Play justification otherwise.

### 5.2 In-process API (`core/InProc.kt`)
`MainActivity.shouldInterceptRequest` answers the WebView's quick local GETs `/api/ls`, `/api/space`, `/api/stat` (only `dev=local`, no `!` archive paths), `/api/job`, `/api/clip`, `/api/info` plus later additions (`/api/peers`, `/api/smb` GET, `/api/arcjob`, `/api/sscanp`, `/api/sscannode`, `/api/sscantop`, `/api/jobs`) by running `Routes.handle` against an in-memory `Exchange`: byte-identical answers, no TCP / thread / HTTP parse. POSTs, `/api/dl`, thumbnails, other devices, SMB, archives, search and any 5xx return `null` and go the HTTP way (WebViewClient cannot see POST bodies). Kill switch `InProc.enabled = false`; answers slower than 300 ms are logged as `LANShare: slow in-process ...`.
Other speed work: `LocalFs.ls` stats folders with >= 150 entries on 4 threads (`statPool`); `Routes ls` lower-cases names once; `ui.html` `prefetch` / `idlePre` warm the listing cache `LSC`, `thBusy < 4`, thumbnails use `/api/thumb` directly, selection toggles avoid a full `render()`, `touch-action: manipulation`. Not done on purpose: in-process thumbnails (would block intercept threads), counts, search, peers / SMB, a native listing cache (stale after other apps' changes).

### 5.3 Jobs, progress card and progress bubble
- `core/Jobs.kt`: every long task (copy, move, send, extract, zip, delete, print, archive listing, duplicate scan, storage scan) is a `Job` in `Jobs.all`, process-wide (survives Activity changes). `Job` carries `cur / curDone / curTotal / files / filesTotal / failed / dest / problems`; `toJson` sends them.
- **Detail card** in `ui.html` (`lvMake / lvFeed / lvEnd`, CSS `.pj`): verb + %, `from > to`, current file with its own bar, Transferred / Speed / Time left / Elapsed / Files n of m / Problems, live problem list, result summary. Opens by itself after 2 s only when the window is >= 400 x 520 px (never over another sheet); *Minimize* leaves the bubble. The merge-copy log and the "replace this file?" question live in the same card. `lvOn()` = card really on screen (it lives in `#sheet`, which ~25 other sheets reuse).
- **Bubble** `#jb` + panel `#jp` live OUTSIDE `#sheet` (fixed, z 21/22, above viewer 20): ring = average %, number = running jobs, `!` / tick when finished. Drag snaps to the nearest corner (`jbc` in localStorage, default top right), tap = panel with one row per job (bar, current file, files i/n, speed, Cancel; tap a row = its detail card; Clear; minimize; tap outside collapses); sized from the window (`min(340px, 100vw - 32px)`, 60 % of `--lvh`). `GET /api/jobs` lists running jobs + ones finished < 10 s ago; polled every 450 ms while something runs (`jbKick`). **Important**: the main file list is a native RecyclerView drawn over the WebView and only lets drawing / touches through "holes" listed in `nlLay()`; `#jb` / `#jp` are holes and `jbRender` / drag call `jbLay()` -> `nlLay(true)` + `nlChPush()`. If the bubble is missing: `chrome://inspect`, check `document.getElementById('jb').style.display` and `await api('GET','/api/jobs')`.
- **Native overlay for screens without a WebView** (`ops/JobView.kt`, `ops/JobOverlay.kt`): read-only rows from `Jobs.all`, cancel sets the same `Job.cancel` flag, finished rows linger 3 s / errors 10 s, bubble with ring, drag + snap (prefs `ops_overlay/corner`), card <= 340 dp, hidden in PiP and when nothing runs. `JobOverlay.install(this)` after `setContentView` in `ImageViewerActivity`, `PdfViewerActivity`, `TextEditorActivity`, `PlayerActivity` and `StorageActivity` (which hides its own `sscan:` job via `hidePrefix`); not in `MainActivity` (page card does it). The foreground notification of `LanShareService` shows running jobs (title = label or "N tasks running", progress bar). Origin: the `progress-overlay-handover-v4` package written for another app; only its missing view part was ported (not `OperationTracker` / `OperationsService`).
- Not done: hinge avoidance (needs androidx.window); notification tap opening the panel.

### 5.4 Resumable transfers (2026-10-18)
A copy / move that loses its link no longer starts the file again; an interrupted job can be continued later.
- **File level** (`Endpoint`): `resumable`, `partial(v, tag)`, `writeResume(v, input, size, offset, tag, cb)` (defaults = not resumable, so `RootFs` / archives unchanged). `LocalFs` and `SmbFs` write `name.lspart` as before but **keep** it when the transfer breaks (a user Cancel still removes it) and append from `offset` when continued. `RemoteFs` asks the other phone `GET /p/partial?path&tag` (answer `{have}`) and uploads the rest with `POST /p/put?path&tag&offset&total` (Content-Length = total - offset); a phone with no `partial` route answers "unknown route" and gets plain whole-file uploads.
- **Identity**: `tag` = `"size:mtime"` of the source; `core/Partials.kt` (`filesDir/partials.json`) stores the tag per `.lspart` (key = absolute path, or `smb|<id>|<share path>.lspart`), so a partial of an older / changed source is never reused and no sidecar files clutter folders. Entries and `.lspart` files older than 7 days are purged in `Core.start`.
- **Job level** (`Jobs.copyFile`): files >= 4 MB (`RESUME_MIN`) whose source can seek continue from the destination's `partial()`; retry with back-off 2 / 4 / 8 / 16 / 30 s ("Connection lost - retrying (n/6)", Cancel works while waiting); an attempt that gains >= 1 MB resets the failure count (cap 40 attempts); other files keep the old 4 tries. `Jobs.work` tracks unfinished top-level items and on an error saves a resume record (`Partials.putJob`: src / dst ids, dest folder, cut, items left, destination names the first run chose); `Jobs.resume(id)` re-runs `work` with conflict `"resume"` (same size = skipped and counted as done, different size = replaced from its `.lspart` when kept; folders keep the first run's names so a half-copied folder continues instead of becoming "name (1)"). Moves delete the original only when every file is complete.
- **API**: `GET /api/resumable`, `POST /api/jobresume?id` (-> `{job}`), `POST /api/resumedrop?id`; `Job.toJson` adds `resume` on an error. **UI**: failed copy card gets **Resume**; Settings > **Interrupted transfers** (only when something is left) lists records with Resume / Forget.
- **Tested** (JVM harness with stubs): `LocalFs.writeResume` + `partial` (keeps part, wrong offset rejected, changed source ignored, cancel removes, target untouched until complete, identical content) and the real `copyFile` against a flaky seekable source. **Not compiled / not device-tested**: `SmbFs.partial/writeResume`, `RemoteFs.partial/writeResume`, `Routes` put / partial, `Jobs.work` resume wiring, `ui.html` bits.
- Check: copy 500 MB phone -> phone, Wi-Fi off 20 s -> "Connection lost" then continues from the same MB; kill the receiving app mid-copy and copy the same folder again -> `.lspart` continues; copy a folder to SMB, pull the cable, Resume -> finished files skipped, no "(1)" folder; edit the source between tries -> restarts from 0.
- Not done: hash check of the kept part; Root / archive sources; a partial left by a Cancel is only purged after 7 days; single-file downloads by viewer / player unchanged.

### 5.5 SMB, FTP, SFTP
- **SMB** (`SmbFs.kt`, smbj): Settings > SMB shares; each saved share is a device that browses, searches, downloads, uploads, copies, renames, deletes and receives "Send to..." (lands in the share root). Use the PC's IP (no NetBIOS names); SMB1-only servers unsupported. Config `CFG["smb"]` = `{id, host, share, user, password, name}`; empty user = guest; the login is tested with `ls("/")` before saving. Optional **Share** field limits a PC to one share.
- **SMB screen** (`openSmb`): one card per saved PC (status dot, name, `\\host\share`, edit / remove with a 3 s "Remove?" second tap), found-on-network list with Rescan (`/api/smbscan`), one Add / Edit form. Edit = `POST /api/smb` with `edit:<id>` -> `Smb.update` (keeps id and position; empty password keeps the stored one; new login tested first; cached connection dropped; open tab reloads at `/`).
- **Duplicate finder on SMB**: `Endpoint.walkEach(v, visit)` streams the walk (reconnect-safe in `SmbFs`); `DupFinder` updates its label every 0.3 s and honours Cancel.
- **FTP / FTPS** (`FtpFs.kt`, saved under `"ftp"` in `lanshare.json`) and **SFTP** (`SftpFs.kt`, trust-on-first-use host key pinned in the saved server): remote files are read-only and seekable (REST + RETR, re-open at the current position after a drop); connections come from a borrowed pool (4 slots, `FtpPool`).
- **FTP listing speed (2026-10-22, 5 parts, Android side not compiled / device-tested)** - goal: folders open as fast as WinSCP / FileZilla.
  - **Cache** (`core/FtpCache.kt`, shared by FTP and SFTP): in-memory LRU (300 folders / 60,000 entries, fresh 30 s, TTL settable 0-3600 s); disk copy `filesDir/ftpcache/<sha1(server id)[0..16]>.json` (per server max 200 folders / 40,000 entries, entries older than 30 days ignored, saved 4 s after the last change). `ls()`: fresh hit = no connection; stale hit = returned at once while ONE background refresh runs (`ftp-refresh`); if the answer differs, `Core.onFtpChanged` -> `window.lsFtpChanged(dev, path)` reloads the open folder. Concurrent identical listings share one request (single-flight). Every write drops the folder, its parents and (remove / rename / move) the subtree (`FtpFs.dirty`). Never cached: `names()`, name-clash checks (rename / move), `fresh=1`.
  - **Protocol savings**: FEAT asked once per server (no MLSD in FEAT -> straight to LIST; with MLST `OPTS MLST type;size;modify;`), `SYST` remembered, symlink answers remembered (`FtpPool.links`), `TCP_NODELAY`. `entry()` (open / stat / walk root / remove) reads the parent's cached listing, else one `MLST <path>` on the control channel (failure falls back to the parent listing; 500-504 sets `FtpPool.noMlst`). Symlinks are resolved after the listing (`resolveLinks`, up to 200 per listing, 4 s budget, helper connections only while >= 2 slots are free). Search / walk / folder totals fill the cache (`listFill`, max 60 folders per operation, not when a write finished meanwhile).
  - **Connections**: `Endpoint.warmUp()` + `GET /api/warm?dev=` (called from `openDev` and on a fresh hit) logs in and parks a connection; keep-alive thread `ftp-keeper` (NOOP to idle connections older than 12 s, closes all idle ones 3 min after last use, `SO_KEEPALIVE`); **prefetch** after each `ls`: parent + first 6 sub-folders on a SPARE connection (only when >= 3 of 4 slots are free, one worker per server, stops when a tap queues); **FTPS session reuse** (one `SSLContext` per server, `ReuseSpi` / `ReuseFactory`, control-port session-cache key) for servers that require it.
  - **UI / tools**: pull-to-refresh sets `S.fresh=1` -> `&fresh=1` -> `Jobs.ep(dev).invalidate(path)`; `GET /api/ftpcache` (stats `{ttl, hits, stale, miss, folders, items, disk, log[]}`, `?clear=1`, `?ttl=`); FTP servers screen (`openFtp`) has a Listing cache block (stats, TTL button 0/10/30/120/600 s, Clear). `tools/ftp_cache_test.py`. SFTP does not log timings.
  - **Check**: open an FTP folder, force-close, Wi-Fi off, reopen -> list from disk; Wi-Fi on + a change from another client -> list reloads by itself; upload / rename / delete from the app -> no stale entry.
- `RemoteThumbs.kt`: thumbnails for other devices / SMB through the endpoint's `Source` (JPEG <= 400 px, disk cache keyed by dev + path + size + mtime), also used by the native list.
- **Google Drive** is the planned fourth remote kind (`gd:` ids, `GdriveFs`, saved under `"gdrive"` in `lanshare.json`): see chapter 17. `Jobs.ep` knows `gd:` since Part 4 (read-only until Part 5).
- No dedicated handover ever existed for FTP / SFTP beyond the above (TLS details, `PeTls` / FTPS option see 10.2).

### 5.6 Root support (2026-10-16)
Settings > **Root access** (off by default) shows the whole file system as one more place, **Root** (device id `root`): browse, open, copy / move / rename / new folder / delete / search / details / duplicate finder via `su`.
- `core/RootShell.kt`: `check()` = `su -c id`, per-command `su -c`, `q()` quoting, per-run `token`, `sign(url)`. `core/RootFs.kt`: `Endpoint` over `find` / `stat -c` / `cat` / `tail -c +N` / `mv` / `rm` / `mkdir` / `df`; written files keep owner + mode of the file they replace, a new file gets its folder's owner; delete is permanent and refuses whole system folders; shell-loop fallback when `find -exec +` is missing.
- Wiring: `Cfg.rootEnabled()` (`root_on`), `Jobs.ep("root")` -> `RootShell.fs()`, `/api/peers` adds Root only when on AND granted, `GET/POST /api/root` (`enable` asks su first, `disable`, `check`), `Core.start` re-checks su, ui.html Settings row (confirm dialog) + cookie.
- **Security**: root is gated by a random per-process token that only exists in the app: the page gets it from `LSAndroid.rootToken()` and keeps it in cookie `lsroot` (`rootCk()`); `Routes.handle` marks a request untrusted (`RootShell.untrusted`) unless it is loopback AND carries the token (cookie / header `x-ls-root` / query `rt`); `Jobs.ep("root")` and every `dev=root` query refuse untrusted requests; native viewers / player / print / share add `rt` with `RootShell.sign()`. `/p/` routes (other devices) never serve root.
- Not done: Storage Analyzer scan of `/` as root, fast root video thumbnails (each seek restarts `tail`), recycle bin for root deletes. **Not compiled / not device-tested.**
- Check on a rooted phone: turn on -> Magisk / KernelSU prompt -> "Root" in the device list; open /data/data, view a picture, copy a file out and in (owner of an overwritten app file must stay the app's), rename, new folder, delete a test folder; switch off -> tab disappears; another app (Termux `curl 127.0.0.1:8765/api/ls?dev=root\&path=/`) must get 403.

### 5.7 Archives, ZIP, ZIP editing
- **Big archives on other devices** (Batch 7): `ArcStore.index` reads only the ZIP end record + central directory with ranged reads (`RangeZip` on any seekable `Source`: `RemoteSource`, `SmbSource`) so listing is instant; odd layouts (`ZipFormat` error) fall back to a full download. Stored entries are served in place through `WindowSource`; deflated ones are inflated into the cache with a progress job. Long steps register a `Job` via `ArcProg`; the UI polls `GET /api/arcjob` and shows the progress toast with Cancel (`/api/jobcancel`; cancelling a listing returns HTTP 499 `cancelled`, the UI goes back to the folder holding the archive). Copy / extract of >= 8 files out of a ZIP on another device first fetches the archive once (`Jobs.pinArchives`).
- **Zip feature**: selection bar > **Zip** (not inside archives). `POST /api/zip {dev, paths, dir, name, replace}` -> `Jobs.startZip / zipWork` streams every file through `Zip64Writer` (data descriptors, ZIP64 only where needed, already-compressed types stored as level-0 deflate), writes `<name>.zip`; local = straight into the folder (`.lspart` -> rename), remote = built in cache then uploaded; Cancel removes the partial. No size limit except free space. `doZip` lists the destination and when `name.zip` exists asks **Replace / Keep both / Cancel** (`dlg` got an optional `alt` button; `finalName` keeps the exact name; the old file is only removed when the new ZIP is complete).
- **More formats open like folders, read-only (2026-10-19)**: 7z / cb7, TAR / cbt, TAR.GZ / tgz, TAR.BZ2 / tbz / tbz2, TAR.XZ / txz, single .gz / .bz2 / .xz (one entry), ZIP-based jar / war / aar / xpi / apks / xapk. `.apk` and office files are deliberately NOT archives. Code: `ArchiveFs.kt` (`arcFmt()`, `ArcIndex(fmt)`, `ArcIndex.unpack`, `ArcStore.otherExtract`), ui.html extension regexes, manifest "Open with" entries. RAR5 and password-protected 7z unsupported (RAR via junrar needs the whole file). TAR / compressed files have no index: a big .tar.gz is unpacked once to list and again to open one file.
- **Archive editing**: `core/ZipEdit.kt` edits zip / cbz in place (adds replace the old central directory and roll back on error; deletes copy the rest raw to a temp file + rename; same name = new added, then old removed; ZIP64 / RAR unsupported; JVM-tested incl. `unzip -t`). `core/ArcEdit.kt` (2026-10-19): 7z, TAR, TAR.GZ/TGZ, TAR.BZ2/TBZ, TAR.XZ/TXZ add / delete / new folder by rewriting to `<name>.edit.part` with commons-compress and renaming; the ZIP family (zip cbz jar war aar xpi apks xapk) uses `ZipEdit`. `ArcEp.editable()` decides by format; RAR and single-file gz / bz2 / xz are read-only with a clear message. Only archives on this phone. `Jobs`: "cut" into an archive = copy; bulk delete = one rewrite (`removeMany`). Route `/api/addzip`; ui.html: Delete, Paste, "Edit ZIP" menu (Add files picker, New folder, Paste, Extract all), `zipEd()` covers the new extensions. Job label "Adding to archive". Not compiled (ArcEdit).
- **Archive details (2026-10-29)**: strip of chips (type, size, files, % saved, password) under the tool row while inside an archive + full sheet on tap; `core/ZipInfo.kt` / `core/ArcInfo.kt`, `/api/arcinfo`, `arcRow()` / `doArcInfo()` in `ui.html`. Test: open a ZIP, a password ZIP, a .7z and a .tar.gz on a phone; the strip must not move the list (fixed height) and the native list must sit right under it.

### 5.8 Recycle bin (`core/Bin.kt`, redesign 2026-10-09)
`openBin()` (ui.html): fixed top bar with **Empty bin**, tap-to-select rows (Select all / Restore / Delete / Clear), rows drawn 80 at a time, progress bar with Cancel. Restore / delete / empty run as ONE background task (`Bin.start` -> `Bin.Task`, `POST /api/bin {op:restore|purge|empty|cancel, ids}` returns at once; `GET /api/bin?items=0` = progress). `Bin.purge` first renames the entry to `.del-<id>` (atomic, vanishes at once) and deletes afterwards; leftovers swept at start (`sweepDeleted`). `Bin.list/restore/purge/empty` no longer hold the global lock. Items are kept `Bin.KEEP_DAYS` days. **Folder view (2026-11-05, chapter 20):** `/.LANShare Bin/<shown name>/...` is a virtual local path (see `Bin.physical`), so the normal file browser can show the bin. Checked in Chromium with a mocked API (400 items).

### 5.9 Folder statistics, albums, media info
- `GET /api/folderstat?dev=local&path=` -> `{files, bytes, partial}` (`LocalFs.stat`: recursive, symlinks skipped, 8 s cap then `partial`, 1 min cache) feeds the home tiles. It is one of the two slow background scans (max 467 ms now, 13).
- `Albums.kt`: gallery albums (MediaStore query, folder-walk fallback); `Albums.total / fullSized` count full-sized pictures only (longest side >= 500 px, or >= 20 KB when unknown; no `thumbnail` / `cache` / `tmp` / sticker / hidden / Android / system folders, no `*thumb*`).
- `Media.kt`: photo dimensions + date taken, video / audio duration + resolution (best effort).
- **Media info in Details (2026-10-21)**: for video / audio, `Media.av` also calls `details()` which adds to the `/api/stat` JSON: `container` `{mime, fmt, bitrate}` (bitrate falls back to size / duration), `tracks` `[{kind: video|audio|text|other, mime, codec, profile?, bitrate?, lang?, w, h, fps, hdr (video), rate, ch (audio)}]` from `MediaExtractor.getTrackFormat`, and `tags` `{title, artist, albumartist, album, track, genre, year, composer, author}` from `MediaMetadataRetriever`. No new library (the MediaInfoLib / FFmpeg options were rejected: native size, and the easy `nextlib-mediainfo` AAR is GPL-3.0). `ui.html` `doDetails` shows Container / Video / Audio / Subtitles / Tags sections above a "File" heading (CSS `.dsec`). Limits: only local files and other LANShare phones with this version (SMB / FTP / SFTP / archive entries have no `Media.info`); `MediaExtractor` reads only what Android's codecs know (no DTS / TrueHD profile, no Dolby Vision profile, bit depth, chroma, or writing application); HDR comes from `color-transfer` (PQ / HLG) only; frame rate may be missing for some MKV files. Test: Details on an MP4 (H.264 + AAC), an MKV with 2 audio + subtitle tracks, an HDR phone video, an MP3 with tags, a corrupt video (must show the basic rows only, no error).

### 5.10 Update check (`UpdateCheck.kt`)
Compares the highest release tag with the installed `versionName` (`isNewer`, "-sha" suffix ignored): same or older = no dialog and no download (manual check toasts "Güncel: <version>"); newer = dialog **İndir / Sonra / Bu sürümü atla** (skip stores a `skip` tag, hides only the automatic prompt for that tag). A manual check ignores the 6 h limit and a skipped version. The old "reinstall latest APK" path is gone.

**Change log in the dialog (2026-10-26, NOT compiled, not seen on a device):** the offer dialog is now a scrollable panel (current version, then **Neler değişti**) built by `changeView` / `notesText` from the `body` of EVERY release newer than the installed version (newest first, 4000 chars max per release; a `null` body or no bullets = "(not listed)"), so a skipped version's notes are not lost. `body` is the top section of `CHANGELOG.md`, extracted by the *Release notes* step of `build-apk.yml` and passed to `softprops/action-gh-release` as `body_path` (no commit-back to the repo; identical-to-previous-release or bullet-less text becomes "Changes not listed for this build." plus a CI warning). Rendering: `### Added` green, `### Removed` red, other `###` headings in the accent colour, `- ` bullets as "•"; `# ` / `## ` lines are skipped. Test: bump nothing, push a change with a new top section, open Settings > Check for updates on an older build, confirm the lists show before **İndir**.

**Edition fix (2026-11-02, NOT compiled, not device-tested):** release selection is now per edition: `isLite(ctx)` (`BuildConfig.LITE` or package `.lite`), `pickApk(assets, lite)`, `hasApk(release, lite)`; a release without the own-edition APK is skipped and the release-page fallback is gone (the page lists `-lite.apk` first, so a full user ended on the lite file). CI: `action-gh-release` now creates a DRAFT; new last step *Publish release* checks both asset names via `gh release view` and runs `gh release edit --draft=false --latest` (before, the smaller lite APK was visible alone for a while).

### 5.11 Model download links (`ModelLinks.kt`)
