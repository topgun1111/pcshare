## Part 1 - what exists (`core/StorageScan.kt`, ~330 lines)
```kotlin
StorageScan.start(dir: File, label: String, usedBytes: Long): Scan   // returns at once; daemon threads (4)
StorageScan.get(id)  StorageScan.cancel(id)  StorageScan.latest(dir)  StorageScan.running(dir)
class Scan { state "run|done|cancel|error", error, cancel, files/dirs/bytes (live AtomicLong), denied, deniedSample, cur,
             percent() (-1 unknown, max 99 until done), millis(), root: SNode?, top: List<SNode>,
             catBytes(), catFiles(), find("/DCIM/Camera") }
class SNode { name, dir, parent, size, files, folders, cat, agg, denied, cats: LongArray?, kids: Array<SNode>, path() }
object SCat { OTHER IMG VID AUD DOC ARC APP, COUNT, KEYS, of(fileName) }
```
Design decisions (why):
- **Memory**: a folder keeps only its 200 largest files as nodes; the rest are ONE synthetic `agg` node (name "", `files` = count) so sums stay exact. Empty folders are dropped from `kids` (still counted in `folders`). Global guard: after 400,000 kept nodes new files are only counted. Finished scans in memory: 3 (`KEEP_SCANS`).
- **Speed**: one task per folder on a 4-thread pool (FIFO = breadth first), one `Files.readAttributes(NOFOLLOW_LINKS)` per entry on API 26+ (dir / link / size in one stat; same reason `LocalFs.ls` does it), `File` API below 26.
- **Symlinks** are skipped (not followed, not counted). Sizes are apparent sizes (`length`), like the rest of the app.
- **Unreadable folders** (Android/data on API 30+, no All-files access): `node.denied`, counted in `Scan.denied`, first 20 paths in `deniedSample`. Part 9 shows "System / other = used - scanned".
- **Categories** by extension (`SCat.of`): images, video, audio, documents, archives, apps (apk, obb ...), other. Bytes per folder in `SNode.cats`; file counts only for the whole scan (`Scan.catFiles()`).
- Folder totals are filled by a finishing pass (post-order, thread with 16 MB stack for deep trees) after the last task; `root` / `top` are only set when the scan is `done`. Cancel or error => no tree.
- Progress: `percent()` = scanned bytes / used bytes of the volume, capped at 99 (unreadable areas keep it from reaching 100 before the end).
- Not done on purpose in part 1: JSON output, routes, caching to disk, any UI, file modification times.

Logic check done: a Java mirror of the walk + finishing pass (same algorithm) run on a generated tree of 703 files / 37 folders (incl. a folder with 500 files to exercise `agg`, empty folders, 4 threads): total size, file count, folder count and category sum all equal the on-disk values, kids sorted, every folder = sum of its kids. The Kotlin file itself has not been compiled.

## Part 2 - what exists (all GET, in `Routes.api`; helpers `sscan*` above `sendFile`)
Category arrays are always in `SCat.KEYS` order: `other img vid aud doc arc app`. Errors use the usual `{error}` + status (404 unknown scan / folder, 400 not finished).
- `/api/sscan?path=/&rescan=0` -> `{id, state, path, whole, error}`. `path=/` = whole main storage (`usedBytes` = total - usable of the root, feeds the percentage); other path = that folder (percentage -1, no used size known). Returns the running scan of that folder if there is one, else the newest finished one, else starts a new scan. `rescan=1` skips the finished one (a running one is still reused). Not in `InProc` (starts work).
- `/api/sscanp?id=` -> `{state run|done|cancel|error, percent (-1 unknown), files, dirs, bytes, used, cur, error, ms, denied, keys, catFiles[7]}`; when `done` also `catBytes[7], total, folders, deniedSample[]`.
- `/api/sscannode?id=&path=/DCIM&n=60` (n 1..500, default 60; only when `done`) -> `{id, path, name, size, files, folders, denied, cats[7], kids[], rest?}`. Kid: `{n, d(dir), s(size), f(files), ...}`; folder kid adds `fo` (sub-folders), `cats[7]`, `x:true` if unreadable; file kid adds `c` (category index); "N small files" row has `a:true`, `n:""`, `f` = count. Kids are biggest first. `rest = {count, s, f}` = the kids cut off by `n`. Root `name` = the scan label ("" for whole storage: UI shows its own title). 404 when the folder is not in the tree (empty folders are pruned).
- `/api/sscantop?id=` -> `{id, top:[{n, p (full path below the scan root), s, c}]}` (100 largest files, biggest first).
- `/api/sscancancel?id=` -> `{ok:true}` (state turns `cancel` once the running tasks notice; no tree then).
- `InProc.ROUTES` got `/api/sscanp`, `/api/sscannode`, `/api/sscantop` (cheap in-memory reads; they are not in `LOCAL_ONLY`, they never touch other devices). `sscan` and `sscancancel` go over HTTP.
- Paths are scan-relative virtual paths (`/` = scan root). For a folder scan, path `/` is the scanned folder itself, so the UI must add the folder's real path when it opens files (part 8).
- Not done on purpose: no disk cache, no `dev` parameter (this phone only; `arcSplit` paths are rejected), no JSON for denied folders beyond `deniedSample`.

Returns the nearest folder still in the tree, null = not a file of this scan (nothing changed). Checked with a Python mirror (3000 random trees: size / files of every folder = sum of the files below after a delete).

## Part 9b - what exists (whole storage + robustness)
- **System / other explained** (`StorageActivity.sysDialog`, note in `buildDone`): at the storage root the note reads "System / other: X (N% of the used space) · what is this?"; a tap opens a dialog with Used / Found by the scan / System / other, what it consists of (Android + updates, apps' private data and caches, other users, block rounding of many small files), the Android 11+ note about `Android/data` and `Android/obb` (closed even with All files access), a line when the scan was made without All files access, the unreadable folders (count + first 8 paths) and, when the access is off, an **Allow access** button. - **All files access**: `needAccess()` = `Core.storageOk == false`. A red banner under the header ("Allow all files access" -> `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`, fallback `ACTION_MANAGE_ALL_FILES_ACCESS_PERMISSION`) while it is off; the same button on the error / cancel message. `Scan.limited` (set in `StorageScan.start` from `Core.storageOk`) marks a partial result: when the user comes back with the access on (`onResume`) the screen says so and rescans by itself (same folder), and a finished / saved limited result is never reused once the access is on.
- **Other volumes (SD card, USB)** (`core/Volumes.kt`, chips under the header, only at the storage root): `Volumes.extra(ctx)` lists mounted non-primary `StorageVolume`s (API 30 `directory`, below that the hidden `getPath()`, fallback `getExternalFilesDirs`). Scans of a volume key on the volume path like any folder. **On another volume: view + Open / Open with / Share only** (FileProvider got `<root-path>`): no Delete (rows, long-press select, confirmations are off), no "Show in file manager" (the file manager only shows the main storage), no "File manager" button. A volume that is removed meanwhile -> back to the internal storage with a toast.
- **Last result remembered** (`core/StorageStore.kt`): a finished scan is saved (gzip, cache folder `sscan/`, one file per scanned folder, newest 4 kept, max age 7 days) at the end of the scan and after every delete in the analyzer (merged, serialized under the scan lock, written outside it). `attach()` order: running scan -> newest finished one in memory -> saved copy (`loadSaved`: "Loading the last result…" on a worker thread, then `StorageScan.adopt`) -> new scan. The summary line says how old it is ("scanned 3 h ago (took 12.4 s)") when it is older than 90 s. Rescan skips the saved copy. Any failure to read = a normal new scan.
- **Rescan polish**: the header Rescan button is hidden while a scan runs (Cancel is in the content); after **Cancel** or an error the earlier finished result of that folder is offered ("Show the previous result (3 h ago)") together with "Scan again"; Rescan inside a folder still returns to that folder (`pendingPath`); the running screen shows elapsed seconds and says the scan keeps running when the screen is left.
- **Scan progress bubble + notification**: every scan is a normal `Job` in `Jobs.all` (key `sscan:<id>`, label "Analyzing storage" / "Analyzing <folder>", bytes / used bytes as progress, indeterminate for a folder scan), mirrored by `StorageScan.mirror` about 6 times a second; the job's Cancel (bubble, notification, web page) sets the scan's cancel flag. The file manager's `JobOverlay` and `LanShareService` show it; the analyzer's own overlay hides it (`JobOverlay.install(this, StorageScan.JOB_PREFIX)` -> `hidePrefix`). The job ends with the scan state.
- **Memory guard**: kept-node limit per scan = heap size / 700 B between 150,000 and 400,000 (`nodeLimit`), plus a live check (less than 32 MB heap left -> stop keeping single files); folders after that only count their files into the "small files" node (`Scan.truncated`, shown as a note; totals stay exact; the Largest list is independent). Finished scans kept in memory: newest 3 **and** at most 700,000 kept nodes together (the newest is always kept); a cancelled / failed scan frees its Largest heap. OOM in a walking thread still ends the scan with "Out of memory".
- **Not done on purpose**: delete / bin / file-manager actions on another volume; saving a partial (cancelled) scan; a volume picker in the web UI; showing the "System / other" block inside the treemap; auto-refresh of a loaded result (it stays as it was, with its age shown).
