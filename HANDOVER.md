## 1. Project at a glance

**What it is.** LANShare is an Android file manager that browses and moves files between this phone, other LANShare phones, SMB / FTP / SFTP servers and a Windows PC on the same network, and also prints, shares text, searches pictures with AI and analyses storage. Pure Kotlin; no Python any more.

**Architecture (one picture in words)**
- **Kotlin core** (`core/*.kt`): an HTTP server (`MiniHttp`, a port from the 8765-8784 range in the Python era - check `Core`) with routes in `Routes.kt`, a job engine (`Jobs`), file systems behind one interface (`Endpoint`: `LocalFs`, `RemoteFs`, `SmbFs`, `FtpFs`, `SftpFs`, `RootFs`, `ArchiveFs`), UDP/TCP discovery (`Discovery`), config in `<filesDir>/lanshare.json` (`Cfg`).
- **UI** = `app/src/main/assets/ui.html` (one large page, ~470 KB) in a `WebView`, plus native Kotlin views painted on top for speed (native file list, path bar, chrome, drawer). `MainActivity.Bridge` is the JS <-> Kotlin interface (`LSAndroid.*`). Quick local GETs are answered in-process (`InProc`) instead of over TCP.
- **Native screens** (plain `Activity`, no Compose, no AppCompat): video player, image viewer / editor, PDF viewer, text editor, Office viewer, Storage Analyzer, Inbox (text sharing).
- **Foreground service** `LanShareService` keeps the process, server and discovery alive; wake / Wi-Fi / multicast locks are held once in `Core.start` (`holdAwake`).
- **PC side** (Windows, Python): `pcprint.py` (print + text inbox service on port 8799, with a small Tk window) and `tools/phone_explorer.py` (opens the phone's FTP share in Explorer; built to an .exe by `build-phone-explorer-exe.yml`).

**Stack and build**
- Gradle (AGP 8.5.2, Kotlin 1.9.24), `minSdk 24`, `targetSdk 34`, ABI filter `arm64-v8a` only (ONNX Runtime + ML Kit took the APK from ~8 MB to ~110 MB before the filter).
- CI `.github/workflows/build-apk.yml`: builds on push to `main` / `master` and on manual dispatch (dispatch also creates a release + tag). Version = `VERSION` (major, now `2`) + next free tag number; `versionCode` = minutes since 2026-01-01 UTC; signed release only when the repo secret `KEYSTORE_B64` (+ `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) exists. Keystore: `keytool -genkey -v -keystore release.jks -alias lanshare -keyalg RSA -keysize 2048 -validity 10000`, then `base64 -w0 release.jks` into the secret.
- Dependencies worth knowing: ONNX Runtime Android (CLIP + PaddleOCR), ML Kit text recognition (unbundled Play Services artifact), Media3 / ExoPlayer 1.3.1 (player), `viewpager2`, `recyclerview` 1.3.2, `swiperefreshlayout`, smbj (SMB), commons-compress 1.21 (kept at 1.21 for minSdk 24) + xz 1.9 (archives), zxing core 3.5.3 (QR), core-ktx 1.13.1. **No** Apache POI / PDF library / Compose by design.
- Language: UI text is English with a few Turkish strings (e.g. the update dialog "Bu sürümü atla"). Older handovers were partly Turkish; this one is English.

**Wire protocol** is unchanged from the Python era: old Python builds and Kotlin builds interoperate (`/p/*` routes between devices, UDP beacon port 48555).

## 5. Platform core (server, protocol, jobs, file systems)

### 5.1 Server, routes and behaviour gotchas
**Summary.** `core/*.kt` serves `assets/ui.html` from `MiniHttp` and answers the `/api/*` and `/p/*` routes (`Routes.kt`). The wire protocol equals the old Python server, so builds interoperate. The Chaquopy / Python era is gone (history in 5.12).

**Gotchas to keep in mind**
- `org.json` **drops a key** on `put(k, null)`: real nulls must be `JSONObject.NULL` (used for `used`, `storage_ok`, `error`, clipboard).
- Query parsing mimics Python `parse_qs`: `+` / `%XX` decoded, **blank values dropped**, first value wins.
- `MiniHttp` does not support chunked request bodies, `Expect: 100-continue` or `HEAD` (the Python server had none either). An error mid-upload closes the connection instead of draining the body.
- Android < 15: never call `removeFirst()/removeLast()` on a `java.util.List`; only on `kotlin.collections.ArrayDeque`.
- `storageOk` is evaluated live on every call. `File.renameTo` is used for rename / move, with copy + delete fallback across volumes (`LocalFs.move`).
- `tcpProbe`: "connection refused" = host up, try the next port; anything else = nobody home (same as Python's errno logic).
- The app's HTTP server answers **any app on the phone** at `127.0.0.1`; anything sensitive (root, 5.6) needs a per-process token.
- Port: the server tries a range (8765-8784 in the Python era); the URL is read back from `Core.url`, so any port works. `Core.url` is published at ~106 ms after process start (13).
- Config: `<filesDir>/lanshare.json` (`Cfg`). SMB passwords are stored in plain text in the app's private storage.

**Discovery** (`Discovery.kt`): UDP beacons (port 48555) + unicast sweep + TCP scan + live checks. Network changes (`ConnectivityManager` default-network callback in `LanShareService`) trigger a debounced rescan.

**Security note**: no PIN / pairing by design; use on trusted Wi-Fi. An opt-in PIN / trusted-networks toggle was never built. `MANAGE_EXTERNAL_STORAGE` is fine for sideloading, needs Play justification otherwise.

### 5.2 In-process API (`core/InProc.kt`)
`MainActivity.shouldInterceptRequest` answers the WebView's quick local GETs `/api/ls`, `/api/space`, `/api/stat` (only `dev=local`, no `!` archive paths), `/api/job`, `/api/clip`, `/api/info` plus later additions (`/api/peers`, `/api/smb` GET, `/api/arcjob`, `/api/sscanp`, `/api/sscannode`, `/api/sscantop`, `/api/jobs`) by running `Routes.handle` against an in-memory `Exchange`: byte-identical answers, no TCP / thread / HTTP parse. POSTs, `/api/dl`, thumbnails, other devices, SMB, archives, search and any 5xx return `null` and go the HTTP way (WebViewClient cannot see POST bodies). Kill switch `InProc.enabled = false`; answers slower than 300 ms are logged as `LANShare: slow in-process ...`.
Other speed work: `LocalFs.ls` stats folders with >= 150 entries on 4 threads (`statPool`); `Routes ls` lower-cases names once; `ui.html` `prefetch` / `idlePre` warm the listing cache `LSC`, `thBusy < 4`, thumbnails use `/api/thumb` directly, selection toggles avoid a full `render()`, `touch-action: manipulation`. Not done on purpose: in-process thumbnails (would block intercept threads), counts, search, peers / SMB, a native listing cache (stale after other apps' changes).

### 5.3 Jobs, progress card and progress bubble
- `core/Jobs.kt`: every long task (copy, move, send, extract, zip, delete, print, archive listing, duplicate scan, storage scan) is a `Job` in `Jobs.all`, process-wide (survives Activity changes). `Job` carries `cur / curDone / curTotal / files / filesTotal / failed / dest / problems`; `toJson` sends them.
- **Detail card** in `ui.html` (`lvMake / lvFeed / lvEnd`, CSS `.pj`): verb + %, `from > to`, current file with its own bar, Transferred / Speed / Time left / Elapsed / Files n of m / Problems, live problem list, result summary. Opens by itself after 2 s only when the window is >= 400 x 520 px (never over another sheet); *Minimize* leaves the bubble. The merge-copy log and the "replace this file?" question live in the same card. `lvOn()` = card really on screen (it lives in `#sheet`, which ~25 other sheets reuse).
- **Bubble** `#jb` + panel `#jp` live OUTSIDE `#sheet` (fixed, z 21/22, above viewer 20): ring = average %, number = running jobs, `!` / tick when finished. Drag snaps to the nearest corner (`jbc` in localStorage, default top right), tap = panel with one row per job (bar, current file, files i/n, speed, Cancel; tap a row = its detail card; Clear; minimize; tap outside collapses); sized from the window (`min(340px, 100vw - 32px)`, 60 % of `--lvh`). `GET /api/jobs` lists running jobs + ones finished < 10 s ago; polled every 450 ms while something runs (`jbKick`). **Important**: the main file list is a native RecyclerView drawn over the WebView and only lets drawing / touches through "holes" listed in `nlLay()`; `#jb` / `#jp` are holes and `jbRender` / drag call `jbLay()` -> `nlLay(true)` + `nlChPush()`. If the bubble is missing: `chrome://inspect`, check `document.getElementById('jb').style.display` and `await api('GET','/api/jobs')`.
- **Native overlay for screens without a WebView** (`ops/JobView.kt`, `ops/JobOverlay.kt`): read-only rows from `Jobs.all`, cancel sets the same `Job.cancel` flag, finished rows linger 3 s / errors 10 s, bubble with ring, drag + snap (prefs `ops_overlay/corner`), card <= 340 dp, hidden in PiP and when nothing runs. `JobOverlay.install(this)` after `setContentView` in `ImageViewerActivity`, `PdfViewerActivity`, `TextEditorActivity`, `PlayerActivity` and `StorageActivity` (which hides its own `sscan:` job via `hidePrefix`); not in `MainActivity` (page card does it). The foreground notification of `LanShareService` shows running jobs (title = label or "N tasks running", progress bar). Origin: the `progress-overlay-handover-v4` package written for another app; only its missing view part was ported (not `OperationTracker` / `OperationsService`).
- Not done: hinge avoidance (needs androidx.window); notification tap opening the panel.

### 5.4 Resumable transfers (2026-10-18)
A copy / move that loses its link no longer starts the file again; an interrupted job can be continued later.
- **File level** (`Endpoint`): `resumable`, `partial(v, tag)`, `writeResume(v, input, size, offset, tag, cb)` (defaults = not resumable, so `RootFs` / archives unchanged). `LocalFs` and `SmbFs` write `name.lspart` as before but **keep** it when the transfer breaks (a user Cancel still removes it) and append from `offset` when continued. `RemoteFs` asks the other phone `GET /p/partial?path&tag` (answer `{have}`) and uploads the rest with `POST /p/put?path&tag&offset&total` (Content-Length = total - offset); a phone with no `partial` route answers "unknown route" and gets plain whole-file uploads.
- **Identity**: `tag` = `"size:mtime"` of the source; `core/Partials.kt` (`filesDir/partials.json`) stores the tag per `.lspart` (key = absolute path, or `smb|<id>|<share path>.lspart`), so a partial of an older / changed source is never reused and no sidecar files clutter folders. Entries and `.lspart` files older than 7 days are purged in `Core.start`.
- **Job level** (`Jobs.copyFile`): files >= 4 MB (`RESUME_MIN`) whose source can seek continue from the destination's `partial()`; retry with back-off 2 / 4 / 8 / 16 / 30 s ("Connection lost - retrying (n/6)", Cancel works while waiting); an attempt that gains >= 1 MB resets the failure count (cap 40 attempts); other files keep the old 4 tries. `Jobs.work` tracks unfinished top-level items and on an error saves a resume record (`Partials.putJob`: src / dst ids, dest folder, cut, items left, destination names the first run chose); `Jobs.resume(id)` re-runs `work` with conflict `"resume"` (same size = skipped and counted as done, different size = replaced from its `.lspart` when kept; folders keep the first run's names so a half-copied folder continues instead of becoming "name (1)"). Moves delete the original only when every file is complete.
- **API**: `GET /api/resumable`, `POST /api/jobresume?id` (-> `{job}`), `POST /api/resumedrop?id`; `Job.toJson` adds `resume` on an error. **UI**: failed copy card gets **Resume**; Settings > **Interrupted transfers** (only when something is left) lists records with Resume / Forget.
- **Tested** (JVM harness with stubs): `LocalFs.writeResume` + `partial` (keeps part, wrong offset rejected, changed source ignored, cancel removes, target untouched until complete, identical content) and the real `copyFile` against a flaky seekable source. **Not compiled / not device-tested**: `SmbFs.partial/writeResume`, `RemoteFs.partial/writeResume`, `Routes` put / partial, `Jobs.work` resume wiring, `ui.html` bits.
- Check: copy 500 MB phone -> phone, Wi-Fi off 20 s -> "Connection lost" then continues from the same MB; kill the receiving app mid-copy and copy the same folder again -> `.lspart` continues; copy a folder to SMB, pull the cable, Resume -> finished files skipped, no "(1)" folder; edit the source between tries -> restarts from 0.
- Not done: hash check of the kept part; Root / archive sources; a partial left by a Cancel is only purged after 7 days; single-file downloads by viewer / player unchanged.

### 5.5 SMB, FTP, SFTP
- **SMB** (`SmbFs.kt`, smbj; originally `smbprotocol` under Python): Settings > SMB shares; each saved share is a chip / device that browses, searches, downloads, uploads, copies, renames, deletes and receives "Send to..." (lands in the share root). Use the PC's IP (Android cannot resolve NetBIOS names); SMB1-only servers unsupported; no remote thumbnails except `RemoteThumbs` (later, see below). Config `CFG["smb"]` = `{id, host, share, user, password, name}`. Empty user = guest; the login is tested with `ls("/")` before saving.
- **SMB screen redesign + edit (2026-10-12)**: `openSmb` (ui.html) shows one rounded card per saved PC (status dot, name, `\\host\share`, chips, edit / remove; second tap on remove = "Remove?" for 3 s), found-on-the-network list with Rescan (`/api/smbscan`), one shared Add / Edit form (inline error). Edit: `POST /api/smb` with `edit:<id>` -> `Smb.update` keeps id and position, empty password keeps the stored one, new login tested first, cached connection / state dropped, the open PC tab reloads at `/`. New optional **Share** field limits a PC to one share.
- **Duplicate finder on SMB**: `Endpoint.walkEach(v, visit)` (default = `walk`) streams the walk (reconnect-safe in `SmbFs`); `DupFinder` updates its label every 0.3 s and honours Cancel (before it looked frozen at "0%").
- **FTP / FTPS** (`FtpFs.kt`, saved under `"ftp"` in `lanshare.json`) and **SFTP** (`SftpFs.kt`, trust-on-first-use host key pinned in the saved server): read-only seekable remote files (REST + RETR / re-open at the current position after a drop), borrowed connection pool. **No handover existed for these two**: treat 5.5 as incomplete and document them when you next touch them.
- **FTP / FTPS speed-up (planned in 5 parts, 2026-10-22; Android side NOT compiled / device-tested)** - goal: opening folders and listing files as fast as WinSCP / FileZilla / Solid Explorer.
  - **Part 1 (written)** - listing engine in `FtpFs.kt` + new `core/FtpCache.kt`: (a) in-memory LRU listing cache (300 folders / 60 000 entries, fresh for 30 s, `FtpCache.freshMs`); `ls()` answers a hit without leasing a connection. (b) Every write drops the folder, all parents and (remove / rename / move) the subtree: `FtpFs.dirty`. `names()` and the name-clash checks (rename / move) never use the cache. (c) `entry()` (used by open / stat / walk / rename / move) reads the parent's cached listing instead of listing the parent again. (d) Single-flight: identical concurrent listings take `FtpCache.lock` and share one request. (e) FEAT asked once per server at the first login (`FtpPool.feat`); no MLSD/MLST in FEAT -> straight to LIST (no failed MLSD per folder); with MLST `OPTS MLST type;size;modify;` is sent per connection (shorter lines). (f) `SYST` remembered per server (`FtpPool.syst`) and applied through `FTPClientConfig` so new connections skip it; only "UNIX"/"WINDOWS" answers are stored. (g) Symlink folder-or-file answers remembered (`FtpPool.links`, no CWD per link on the next listing). (h) `TCP_NODELAY` on the control socket. (i) `Endpoint.invalidate(v)` (default no-op) + route `GET /p/ls?path=..&fresh=1` drops the cached listing first - the UI does not send `fresh=1` yet (part 5).
  - **Part 2 (written 2026-10-22, not compiled / not device-tested)** - disk-saved listings + stale-while-revalidate. `FtpCache.init(filesDir)` (called in `Core.start`) keeps a copy of every listing in `filesDir/ftpcache/<sha1(server id)[0..16]>.json` (`{v:1, d:{abs:{at, i:[Item json]}}}`; per server max 200 folders / 40 000 entries, entries older than 30 days ignored, saved 4 s after the last change via tmp + rename; unreadable file = empty). `FtpCache.getStale(id, abs)` = newest known listing of ANY age (memory, then disk). `drop` / `clear` also drop the disk copy, so every write / `fresh=1` / `names()` still reaches the server. `FtpFs.ls`: fresh hit -> as before; else stale hit -> returned at once and `refreshLater` runs ONE background `listCached(fresh=true)` per folder (daemon thread `ftp-refresh`); if the answer differs, `Core.onFtpChanged(dev, v)` -> `MainActivity` -> `window.lsFtpChanged(dev, path)` (ui.html) -> `load()` when that folder is still open. Offline = old list stays. Never stale: `entry()`, `names()`, rename / move clash checks, walk / search. `FtpCache.clearAll()` exists for the part 5 button. **Check**: open an FTP folder, force-close the app, turn Wi-Fi off, reopen the folder -> list appears from disk; Wi-Fi on + add a file on the server from another client -> list reloads by itself within a few seconds; upload / rename / delete from the app -> no stale entry after; `filesDir/ftpcache` files exist after ~4 s.   - **Part 3 (written 2026-10-22, not compiled / not device-tested)** - warm connections, keep-alive, prefetch, FTPS session reuse (all in `FtpFs.kt`, + `Endpoint.warmUp()`, `GET /api/warm?dev=`, `FtpCache.getSince`). (a) **Warm-up**: `ui.html openDev` calls `/api/warm` for `ftp:` servers; `FtpFs.ls` also calls it on a fresh cache hit. `warmUp()` (daemon `ftp-warm`, skipped when a connection is idle / a warm-up runs / the port probe says down) logs in (FEAT, OPTS, TLS, TYPE) and reads the start folder, then parks the connection in the pool. (b) **Keep-alive**: daemon `ftp-keeper` (every 6 s) sends NOOP to idle connections older than 12 s (`KEEP_EVERY_MS`), drops dead ones, and closes ALL idle ones 3 min after the server was last used (`KEEP_MS`, `FtpPool.lastUse`); `SO_KEEPALIVE` on the control socket. The old NOOP-on-lease (>25 s idle) stays as a safety net. (c) **Prefetch**: after every `ls` (not `names()`), `prefetchAround` lists the parent + the first 6 sub-folders (A-Z) into the cache on a SPARE connection (`leaseSpare`: only when >= 3 of the 4 slots are free; one worker per server `FtpPool.pfBusy`; stops when a tap queues; same folder not twice within 20 s `pfAt`; depth 1; errors ignored; no `Ftp.state` change). `listCached(fresh=true)` now reuses a listing stored while it waited for the lock (`FtpCache.getSince`). (d) **FTPS session reuse**: one `SSLContext` per server (`FtpPool.tls`) wrapped per client by `ReuseSpi` / `ReuseFactory`, which gives every layered (data) socket the CONTROL port as session-cache key, so JSSE / Conscrypt resume the control session on data connections (servers with "require TLS session reuse") and on new control connections (one handshake less). Accept-all trust manager as before. **Check**: open an FTP server -> a login shows in the server log BEFORE the first tap, the first tap is instant; browse into a sub-folder you did not open -> instant (prefetched); idle 1 min -> still one connection (NOOP in the server log), after ~3 min it logs out; FTPS server with "require TLS session reuse" (vsftpd `require_ssl_reuse=YES`, FileZilla Server): listing / download work; a plain FTPS server still works. **Risk spots (compile)**: `ReuseSpi` (`SSLContextSpi` protected overrides, `object : SSLContext(spi, provider, protocol) {}`), `FTPSClient(false, ctx)` ctor, `ArrayDeque.remove(element)` in `keep()`. **Risk (runtime)**: TLS 1.3 session tickets - if a server rejects the resumed ticket on the data channel, force TLS 1.2 for that server (`sslContext` protocol) or drop `ReuseFactory`; the keeper holds at most 4 logins per server, so servers with 1-2 logins per IP may need `Semaphore(4)` lowered (not changed here).
  - **Part 4 (written 2026-10-22, not compiled / not device-tested)** - MLST stat, cache fill, faster symlink checks, same cache for SFTP (`FtpFs.kt`, `SftpFs.kt`, `FtpCache.kt`). (a) **MLST stat**: `entry()` (open / stat / walk root / remove) first reads the parent's fresh cached listing (no round trip); on a miss, with MLST in FEAT, `mlstEntry()` sends one `MLST <path>` on the control channel (no data connection, no parent listing). Any failure (550, odd reply, unknown type) falls back to the parent listing; 500-504 / a malformed reply sets `FtpPool.noMlst` (never tried again). Name-clash checks (rename / move, `fresh = true`) still list the parent. (b) **Cache fill**: `listFill()` is used by search, walk and folder totals (stat). Search + totals take a fresh cached listing when there is one; walk (copy / move / zip source) always asks the server but stores the answer. `FtpCache.fill()` stores at most 60 folders per operation (`FtpCache.Fill`) and NOT when a write finished after the listing started (`FtpPool.dirtyAt`, set by `dirty()`). (c) **Symlinks**: `listRaw` collects the links first, then `resolveLinks()` (CWD each; up to 200 per listing, 4 s budget); with 8+ links up to 2 helper connections (`leaseHelper`: only while >= 2 slots are free, so a tap always has one) work the same queue. (d) **SFTP**: same `FtpCache` (fresh hit, stale-while-revalidate from memory / disk, single-flight, `Core.onFtpChanged` reload) - `ls`, `names` (never cached), `invalidate`; every write (mkdir / write / writeResume / setMtime / remove / rename / move) calls `dirty()` (folder, parents, subtree). `entry()` stays a plain `stat` (exact size of links, nothing cached). ### 5.6 Root support (2026-10-16)
Settings > **Root access** (off by default) shows the whole file system as one more place, **Root** (device id `root`): browse, open, copy / move / rename / new folder / delete / search / details / duplicate finder via `su`.
- `core/RootShell.kt`: `check()` = `su -c id`, per-command `su -c`, `q()` quoting, per-run `token`, `sign(url)`. `core/RootFs.kt`: `Endpoint` over `find` / `stat -c` / `cat` / `tail -c +N` / `mv` / `rm` / `mkdir` / `df`; written files keep owner + mode of the file they replace, a new file gets its folder's owner; delete is permanent and refuses whole system folders; shell-loop fallback when `find -exec +` is missing.
- Wiring: `Cfg.rootEnabled()` (`root_on`), `Jobs.ep("root")` -> `RootShell.fs()`, `/api/peers` adds Root only when on AND granted, `GET/POST /api/root` (`enable` asks su first, `disable`, `check`), `Core.start` re-checks su, ui.html Settings row (confirm dialog) + cookie.
- **Security**: root is gated by a random per-process token that only exists in the app: the page gets it from `LSAndroid.rootToken()` and keeps it in cookie `lsroot` (`rootCk()`); `Routes.handle` marks a request untrusted (`RootShell.untrusted`) unless it is loopback AND carries the token (cookie / header `x-ls-root` / query `rt`); `Jobs.ep("root")` and every `dev=root` query refuse untrusted requests; native viewers / player / print / share add `rt` with `RootShell.sign()`. `/p/` routes (other devices) never serve root.
- Not done: Storage Analyzer scan of `/` as root, fast root video thumbnails (each seek restarts `tail`), recycle bin for root deletes. **Not compiled / not device-tested.**
- Check on a rooted phone: turn on -> Magisk / KernelSU prompt -> "Root" in the device list; open /data/data, view a picture, copy a file out and in (owner of an overwritten app file must stay the app's), rename, new folder, delete a test folder; switch off -> tab disappears; another app (Termux `curl 127.0.0.1:8765/api/ls?dev=root\&path=/`) must get 403.

### 5.7 Archives, ZIP, ZIP editing
- **Big archives on other devices** (Batch 7): `ArcStore.index` reads only the ZIP end record + central directory with ranged reads (`RangeZip` on any seekable `Source`: `RemoteSource`, `SmbSource`) so listing is instant; odd layouts (`ZipFormat` error) fall back to a full download. Stored entries are served in place through `WindowSource`; deflated ones are inflated into the cache with a progress job. Long steps register a `Job` via `ArcProg`; the UI polls `GET /api/arcjob` and shows the progress toast with Cancel (`/api/jobcancel`; cancelling a listing returns HTTP 499 `cancelled`, the UI goes back to the folder holding the archive). Copy / extract of >= 8 files out of a ZIP on another device first fetches the archive once (`Jobs.pinArchives`).
- **Zip feature**: selection bar > **Zip** (not inside archives). `POST /api/zip {dev, paths, dir, name, replace}` -> `Jobs.startZip / zipWork` streams every file through `Zip64Writer` (data descriptors, ZIP64 only where needed, already-compressed types stored as level-0 deflate), writes `<name>.zip`; local = straight into the folder (`.lspart` -> rename), remote = built in cache then uploaded; Cancel removes the partial. No size limit except free space. `doZip` lists the destination and when `name.zip` exists asks **Replace / Keep both / Cancel** (`dlg` got an optional `alt` button; `finalName` keeps the exact name; the old file is only removed when the new ZIP is complete).
- **More formats open like folders, read-only (2026-10-19)**: 7z / cb7, TAR / cbt, TAR.GZ / tgz, TAR.BZ2 / tbz / tbz2, TAR.XZ / txz, single .gz / .bz2 / .xz (one entry), ZIP-based jar / war / aar / xpi / apks / xapk. `.apk` and office files are deliberately NOT archives. Code: `ArchiveFs.kt` (`arcFmt()`, `ArcIndex(fmt)`, `ArcIndex.unpack`, `ArcStore.otherExtract`), ui.html extension regexes, manifest "Open with" entries. RAR5 and password-protected 7z unsupported (RAR via junrar needs the whole file). TAR / compressed files have no index: a big .tar.gz is unpacked once to list and again to open one file.
- **Archive editing**: `core/ZipEdit.kt` edits zip / cbz in place (adds replace the old central directory and roll back on error; deletes copy the rest raw to a temp file + rename; same name = new added, then old removed; ZIP64 / RAR unsupported; JVM-tested incl. `unzip -t`). `core/ArcEdit.kt` (2026-10-19): 7z, TAR, TAR.GZ/TGZ, TAR.BZ2/TBZ, TAR.XZ/TXZ add / delete / new folder by rewriting to `<name>.edit.part` with commons-compress and renaming; the ZIP family (zip cbz jar war aar xpi apks xapk) uses `ZipEdit`. `ArcEp.editable()` decides by format; RAR and single-file gz / bz2 / xz are read-only with a clear message. Only archives on this phone. `Jobs`: "cut" into an archive = copy; bulk delete = one rewrite (`removeMany`). Route `/api/addzip`; ui.html: Delete, Paste, "Edit ZIP" menu (Add files picker, New folder, Paste, Extract all), `zipEd()` covers the new extensions. Job label "Adding to archive". Not compiled (ArcEdit).

## 6. UI layer (ui.html, native list, main menu, gallery)

### 6.1 How the UI is built
- `assets/ui.html` owns screens and logic (single page, ~470 KB, ~224 DOM nodes at rest, ~10 MB JS heap, main script runs in 31-53 ms). `MainActivity.Bridge` (`LSAndroid.*`) is the JS <-> Kotlin interface; `onNewIntent` -> `handleShare` handles share intents (`ACTION_SEND`, `ACTION_SEND_MULTIPLE`).
- **Twin rule**: whatever Kotlin paints natively (list rows, path bar, chrome, drawer, search row) has an unchanged HTML twin underneath. The twin is the fallback and the source of truth for taps: native taps come back as `nlOn(...)` / `nlCh(...)` / `nlDr(...)` and click the same HTML element. Row builders exist twice (`NlModel.rows` in Kotlin, `nlBuild` in ui.html) and their `sig` (signature) must stay equal or rows flicker - when you add a row field, change **both** and include it in `sig`.
- **Holes**: the native list is a RecyclerView over the WebView; it lets drawing and touches through only for the rects `nlLay()` reports (`#fab #toast #dlw`, open sheets, `#jb`, `#jp`). A new floating element must be added there. Overlays that hide the native list / chrome / search / swipe (`#gal`, `#pv`, `#home`) are in the same lists (`nlLay`, search push, `nlChPush`, swipe `blocked`).
- Theme: page tokens `--sel --cont --ac ...`; `AppPal.kt` mirrors the page palette (from `nlPalette()`) in memory + SharedPreferences so native screens (Storage Analyzer) use the app's theme. `nlTheme()` (theme picker + system listener) re-pushes palette, chrome, search and layout (a theme change used to leave the list half-themed; `NlHeadView.pal` setter now sets `dirty`).
- Testing UI-only changes: `node --check` of the extracted JS, Chromium with mocked `api()`; `chrome://inspect` on the device.

## 7. Viewers and editors (video, image, PDF, text)

All are plain `Activity` classes (no AppCompat, no Compose), hand-built views, `JobOverlay.install(this)` after `setContentView`. They only accept `http://127.0.0.1` / `localhost` URLs (the local server's `/api/dl`, which does Range requests, so local / peer / SMB files stream without downloading). Handover of a list to a viewer goes through a static `pending` object (no Binder size limit). **Not compiled / not device-tested in the notes** (see section 2).

### 7.1 Video player (`PlayerActivity.kt`, `PlayerWidgets.kt`)
- Media3 / ExoPlayer 1.3.1 (`media3-exoplayer`, `media3-ui`). Tapping a video calls `LSAndroid.play(json)` (`MainActivity.Bridge.play`) with the folder's videos as a playlist: `{start, items:[{name, url, key, subs:[{name, url}]}]}`. Browsers (no `LSAndroid.play`) keep the HTML5 viewer (`openMedia`); inside it a play button / the error box offer "Play in player".
- MKV / AVI / MOV / WebM / MP4 / FLV / MPEG, audio + subtitle track menus, speed, next / previous, resume position (SharedPreferences `ls_player`, key `dev|path|size`), **PiP** (Home while playing, or the button), double-tap +-10 s, swipe left = brightness / right = volume, Fit / Zoom / Stretch, rotate, auto landscape for wide videos.
- Sidecar subtitles (same base name, `.srt .vtt .ass .ssa`) fetched, converted to UTF-8 (windows-1254 fallback) into `cache/subs` and attached.
- Manifest: `PlayerActivity` is its own task (`singleTask`, empty affinity) so PiP works; theme `Theme.LANShare.Player`. No background-audio service (audio stops when the screen is off / PiP closed). `PlayerWidgets.kt`: colours (light = white page, dark = black) and canvas-drawn icons (no drawable resources or font glyphs).

### 7.2 Image viewer (`ImageViewerActivity.kt`, `androidx.viewpager2`)
- `LSAndroid.viewImages(json)` = `{start, items:[{name, url, size}]}` in the current sort order. Each picture is fetched from `/api/dl` into `cache/img/<n>.bin`, decoded with `inSampleSize` (longest side <= 3072 / 4096 px by memory class, never above the 4096 GPU limit), EXIF-rotated, kept in an LruCache with the neighbours preloaded. `ZoomImageView` (`ScaleType.MATRIX`): pinch, double-tap (fit <-> 2.5x), pan, at the edge of a zoomed picture the drag becomes a page swipe. Tap hides the bars. `.gif` / `.svg` (and `.heic` below Android 9, `LSAndroid.sdk()`) go to the HTML viewer. Originals above ~4096 px are not shown at full pixel resolution.
- **Top bar redesign (2026-10-10)**: two lines - middle-ellipsized file name + `date · time`; position in a pill at the bottom centre (`countPill`); drawn Material icon buttons (`IconBtn`, 44 dp): text layer (T), edit, share, and a **⋮ menu** (Slideshow / Stop slideshow, **Details**: name, modified, pixels, size, position). Slideshow 4 s, stops on manual swipe.
- Text layer / OCR: see 11.2. Viewer also reads `OcrPrefs` and has `AutoOcr`.

### 7.3 Image edit (`ImageEditActivity.kt`, 2026-10-08)
Pencil button in the viewer: rotate left / right, drag-to-crop, resize by px or 100 / 75 / 50 / 25 %. Preview is a 2048 px bitmap; on Save the operations are applied once to the original at full resolution (`ImgEdit.render`: EXIF orientation -> rotation -> crop -> scale, one Canvas pass). Save as copy (`name (edited).ext` next to the original; for peers / SMB / archive entries into `Pictures/LANShare Edited`) or replace the original (this phone, jpg / png / webp only); the viewer reloads the page after a replace and drops the page's OCR cache.

### 7.4 PDF viewer (`PdfViewerActivity.kt`)
- Built on `PdfRenderer` (so: no document search, no in-page selection, no links, and **no streaming** - it needs the whole file).
- **Viewer 1 (2026-10-10)**: fast scroller (`PdfScrollBar`, right edge, bubble `page / total`); page **overview grid** (▦, 3 columns, 5 from 600 dp; thumbnails 260 px on the `pdf-render` thread, 12 MB cache); **page text** (T): renders the current page up to 2400 px and reads it with OCR into a selectable dialog with Copy / Share (works for scans; OCR, not the PDF's own text).
- **Viewer 2 (2026-10-10)**: after scrolling stops the next two and previous page are pre-rendered (`prefetch`, `ahead` set; a page with no picture first gets a quick 1/3-size render); in the overview, long-press selects pages (tap toggles, All / clear), bottom bar **Print** (all pages when none selected), **Save PDF** (to Downloads, `name (p. 3-5).pdf`, MediaStore on API 29+), **Share**. Print uses the system print dialog (`PrintDocumentAdapter`): the whole document goes as the original file; selected pages / a range are rebuilt by `JpegPdfWriter` (one JPEG per page at ~180 dpi, one bitmap in memory; text in such copies is not searchable). **Big files**: from other devices / SMB, kept in `cache/pdfc` for 12 h (400 MB cap, oldest first; same key + size = same file, so a same-size edit shows stale up to 12 h), interrupted downloads resume with a Range request (3 tries); local files read fresh.

### 7.5 Text editor (`TextEditorActivity.kt`, `CodeHl.kt`, `MdRender.kt`)
**No handover existed for these.** What the code headers say: `CodeHl` = small dependency-free syntax highlighter (`scan` returns packed triples start / end / kind); `MdRender` = light Markdown -> blocks for the editor's preview (headings with slugs / outline, bold / italic / strike, `code`, nested bullet / numbered / task lists, nested quotes, rules, links incl. `#anchor` and reference links, front matter, simple HTML; no library, no WebView). ## 8. Office files (Word / Excel / PowerPoint)

### 8.1 Summary and design decisions
Replaces the old read-only "docx -> Markdown" viewer with proper support: view `.docx .xlsx` (+ `.xlsm .xltx`), `.xls`, `.doc`, `.odt`, `.ods`, `.pptx`, `.odp`; edit text / cells in place without destroying the rest of the file (docx, xlsx); create new files; search, print / PDF, CSV export, thumbnails, launcher shortcuts.
Decisions to keep:
- **No new Gradle dependencies** (no Apache POI: too big / slow, needs API 26+ parts). Own streaming parsers.
- Package `com.lanshare.app.core.office`: pure Kotlin + `java.util.zip`, **no `android.*` imports**, so it runs on a plain JVM. Own pull parser `MiniXml` (local names only; `rawAttr("r:id")` when needed).
- Files open from a **local `File`** (callers copy remote / SAF / SMB files into cache first).
- **Edit strategy**: patch the XML in place and re-zip, copying every other entry byte-for-byte (styles, images, charts, macros survive). Never regenerate a workbook / document from the model.
- Limits protect the phone: 64 MB per part, 5000 rows x 200 cols / 250k cells per sheet (`XSheet.truncated`).

## 9. Printing and the PC print service

### 9.1 Overview
Three ways to print, all from the same print dialog in `ui.html` (`doPrint`, `printOptions` for PC, `wifiOptions` for Wi-Fi printers):
- **PC** (`pcprint.py`, Windows service on port **8799**, LAN / Tailscale clients only): the phone converts what it can, sends the file with option query parameters; the PC lays it out and prints (SumatraPDF / Office / LibreOffice).
- **Wi-Fi printers** (no PC): found with mDNS / DNS-SD (`_ipp._tcp`, `WifiPrinters.kt`, ids like `wifi:192.168.1.50:631/ipp/print`), printed over IPP (`Ipp.kt`, `WifiPrint.kt`).
- **This phone** through the Android print system (`PhonePrint.kt`: ONE print job for all selected files, PDFs keep their real page count). `PcPrintService` also makes LANShare appear as a printer ("LANShare - print on PC") in Android's own print dialog so "Print" in any app can pick it; the finished PDF is copied to `<storage>/LANShare Shared/`.

### 9.3 What can be printed, and the layout options
- **Conversion on the phone** (`core/PrintPrep.kt`, called from `Jobs.printWork`): webp / heic / heif / avif / ico / wbmp / dng / jfif -> JPEG (`Thumbs.forPrint`); html / htm / xhtml / svg -> PDF (`android/print/WebPdf.kt`: WebView print adapter, no JS, no network; deliberately in package `android.print` because the callback constructors are package-private); ~100 code / config / text extensions -> `.txt`; **unknown / missing extensions are sniffed** (PDF, RTF, OOXML / OpenDocument zip entries, legacy OLE by stream name, decodable picture, HTML / SVG, UTF-16 / UTF-8 text). Video / audio / archives / binaries (`NO` set) and unknown files > 120 MB are refused up front. Office files need Word / Excel / PowerPoint or LibreOffice on the PC for layout options (no native docx renderer on the phone); without a converter the file is printed by its own app (printer + copies only) plus a note.
- **Options** (dialog `PRN_DEF` -> `Jobs.PRINT_KEYS` -> query string -> `pcprint.py parse_opts`): `fit` (shrink / fit / noscale / `fill` = cover and crop), `margin` (0-72 pt, `''` = old default per kind; sent as strings so `'0'` = "None" survives the drop-empty filter), `scale` (10-500 %, overrides `fit`), `align` (`''` centre / `top` / `topleft`), `autorot`, `paper`, duplex / colour (SumatraPDF). With none of the new options set everything behaves as before (old `fit` goes straight to SumatraPDF). Pictures: Scaling = Fit / Fill + Margins (custom scale, position, turn-pages are document-only). Text files: margin = page margin, custom scale = font size. When a paper size is chosen the finished PDF goes to Sumatra as `noscale`. Printers cannot print the last ~3-5 mm, so margin "None" is clipped by hardware. Not tested on a real printer / SumatraPDF (rendered with pdftoppm only).
- **Trim blank edges** (`fit=trim`, pictures only, 2026-10-10): the preview measures each picture's content box (`pvBBox`: outer lines of one flat colour equal to that edge are dropped, 1.5 % safety margin) and sends `crops` (fractions per file); the phone crops the real file before it goes out (`PrintPrep.cropBox` / `trim`, used in `Jobs` PC printing and `PdfPrint.load`; `PhonePrint.prepare`; `WifiPrint.work` / `mergeImages`), then the normal fit logic applies; `pcprint.py` needs no change (unknown `fit` = shrink).
- **One job, no doubles**: `Jobs.printWork` sends `join=1` + `batch`, `idx`, `n` when *Print all files as one job* is on (mixed files, not picture-sheet mode); a file that cannot be sent gets `skip=1` (`skipBatchSlot`); every file carries `key=k<batch>-<index>`. Tested against `pcprint.py` on Linux with a stub.

### 9.4 Previews (`core/PrintPreview.kt`, 2026-10-04)

PDF rendered natively; html / svg / unknown / webp-heic-avif converted by `PrintPrep` first; **office files converted by the PC** (`POST /convert`); text / code files drawn in the UI with the same wrapping as `txt_to_pdf` (page / line counts checked identical). The rotate button right of the preview caption (`pvRotBtn`, `pvTurn`) turns the preview 90 deg clockwise - view only, not saved.
First check after a build: `WebPdf.kt` compiles and an `.html` and an `.svg` print.

### 9.5 Wi-Fi printers (IPP)
`Ipp.printerAttrs` asks for `pwg-raster-document-resolution-supported` / `-sheet-back` (`WifiPrinters.P.rasterDpi`, `.sheetBack`). Printers without PDF but with `image/pwg-raster` (e.g. Brother DCP-T830DW) get ALL pages as ONE raster job (`WifiPrint.pwgRaster` / `writeRasterPixels`) so two-sided printing works (before, the per-page JPEG fallback made every page its own sheet). Landscape pages (2-up) are turned 90 deg clockwise; back sides use the printer's sheet-back transform. **Not tested on the printer**: check with 4 numbered pages; if backs come out upside down flip the sheet-back mapping in `pwgRaster`. ### 9.7 Print space (planned in 10 parts, 2026-10-21; all 10 parts written, 3b + 9b added 2026-10-21; part 10 = compile + device run still open; Android side NOT compiled / NOT device-tested; `SheetLayout.kt` + `PsLayoutJson.kt` JVM-compiled and self-tested)
**Goal.** A drawer entry **Print space**: send pictures from the gallery (and file browser / viewer / share sheet) into a holding area that stores copies, then lay them out several per sheet on one or both sides and send the result to a printer (PC, Wi-Fi IPP, this phone).

**Design decisions**
- **Copies, not links.** Pictures are copied to `<root>/.LANShare Print/<id>/<name>` (like the Recycle bin, `core/PrintSpace.kt`, manifest `items.json`, `.nomedia`). Deleting or editing the original later does not change a pending print. Cap: 500 pictures, 99 copies each.
- **Reuse the print pipeline.** Stored files are normal local virtual paths, so `doPrint(preset, cx)` (`cx = {items, path, dev:'local', full:true, done}`) and `printOptions` (pictures per sheet, preview, margins, duplex) work on them unchanged. The first usable Print button (part 2) just calls it. Own layout code is only for what the dialog cannot do: choosing which picture goes on the front or the back of a sheet.
- **Sidebar.** One `dItem` in `drawerRender()` (tab 0, near *Recycle bin*) -> `openPrintSpace()`; the screen is a page overlay `#ps` like `#gal` / `#pq`, so it must be added to `nlLay` holes and to the lists that hide the native list / chrome / search / swipe (see 6.1 "Holes").
- **Both sides.** Sheet model = `{paper, margin, gap, cols, rows, flip: long|short}`; each sheet has a front and a back list of slots. Back slots are mirrored for short-edge flip so the picture on the back lines up behind the picture on the front. Printers without duplex: print fronts, prompt, print backs (manual duplex).
- **Per picture**: `copies` (1-99) and `rot` (0/90/180/270) are already in the manifest for the layout parts.

**API (Routes.kt)**: `GET /api/ps` -> `{items:[{id,name,size,from,at,copies,rot,path}], count, bytes, max}`. `POST /api/ps` body `{op:"add",dev:"local",paths:[...]}` -> also `{added, skipped:[{name,why}]}`; `{op:"rm",ids:[...]}`; `{op:"clear"}`; `{op:"move",id,to}`; `{op:"set",id,copies?,rot?}` (part 9a: also `ids` + `rotBy`, and `{op:"undo"}` after rm / clear; answers carry `undo:N`). Every POST answers with the new list.

### 12.3 Scan engine (`core/StorageScan.kt`)
```kotlin
StorageScan.start(dir: File, label: String, usedBytes: Long): Scan   // returns at once; 4 daemon threads
StorageScan.get(id) / cancel(id) / latest(dir) / running(dir) / adopt(...) / removeFile / removeNode / pruneNested / deniedBelow
class Scan { state "run|done|cancel|error", error, cancel, files/dirs/bytes (live AtomicLong), denied, deniedSample, cur,
             percent() (-1 unknown, max 99 until done), millis(), root: SNode?, top: List<SNode>, catBytes(), catFiles(), find("/DCIM/Camera"),
             limited, truncated, loaded, removed, job }
class SNode { name, dir, parent, size, files, folders, cat, agg, denied, cats: LongArray?, kids: Array<SNode>, path() }
object SCat { OTHER IMG VID AUD DOC ARC APP, COUNT, KEYS, of(fileName) }
```
- **Memory**: a folder keeps only its 200 largest files as nodes; the rest are ONE synthetic `agg` node (`name ""`, `files` = count) so sums stay exact; empty folders are dropped from `kids` (still counted in `folders`). Kept-node limit per scan = heap size / 700 B between 150,000 and 400,000 (`nodeLimit`) plus a live check (< 32 MB heap left = stop keeping single files; `Scan.truncated` note). Finished scans in memory: newest 3 and <= 700,000 kept nodes together.
- **Speed**: one task per folder on a 4-thread pool (FIFO = breadth first); one `Files.readAttributes(NOFOLLOW_LINKS)` per entry on API 26+, `File` API below. Symlinks skipped; sizes are apparent (`length`). Folder totals filled by a finishing pass (post-order, 16 MB stack thread); `root` / `top` only set when `done`; cancel / error = no tree.
- **Unreadable folders** (Android/data on API 30+, no All-files access): `node.denied`, `Scan.denied`, first 20 paths in `deniedSample`. Categories by extension (`SCat.of`): images, video, audio, documents, archives, apps (apk, obb...), other; bytes per folder in `SNode.cats`, file counts only for the whole scan.
- **Job**: every scan is a normal `Job` (`sscan:<id>`, label "Analyzing storage" / "Analyzing <folder>", bytes / used bytes as progress, indeterminate for a folder scan), mirrored by `StorageScan.mirror` ~6 times a second; the job's Cancel sets the scan's cancel flag. The analyzer's own `JobOverlay` hides it (`hidePrefix`).
- **Delete patching** (`removeFile` / `removeNode`, synchronized on the scan; `dropEmptyAndResort` shared): detach the node, subtract size / files / `1 + folders` / `cats[]` up the chain, drop emptied ancestors, re-sort, remove from `Scan.top`, adjust `files` / `bytes` / `removed`; return the nearest folder still in the tree. `catF` is deliberately NOT adjusted after a folder delete. `Scan.removed` is added back into "System / other" (the bytes are still on the volume in the bin). `pruneNested(ticked)` drops duplicates, nodes inside another ticked node, a second node for the same file (kept node + Largest copy), the "small files" node and the scan root.

### 12.4 API (all GET in `Routes.api`; helpers `sscan*`)
Category arrays always in `SCat.KEYS` order `other img vid aud doc arc app`. Errors use `{error}` + status (404 unknown scan / folder, 400 not finished).
- `/api/sscan?path=/&rescan=0` -> `{id, state, path, whole, error}` (`path=/` = whole main storage, `usedBytes` = total - usable of the root; other path = that folder, percentage -1). Returns the running scan of that folder, else the newest finished one, else starts one; `rescan=1` skips the finished one. Not in `InProc`.
- `/api/sscanp?id=` -> `{state, percent, files, dirs, bytes, used, cur, error, ms, denied, keys, catFiles[7]}` (+ when done `catBytes[7], total, folders, deniedSample[]`).
- `/api/sscannode?id=&path=/DCIM&n=60` (n 1..500) -> `{id, path, name, size, files, folders, denied, cats[7], kids[], rest?}`; kid `{n, d, s, f, ...}` (folder adds `fo`, `cats[7]`, `x:true`; file adds `c`; "N small files" = `a:true`, `n:""`); `rest = {count, s, f}`. Paths are scan-relative (`/` = scan root; for a folder scan add the folder's real path to open files).
- `/api/sscantop?id=` -> `{id, top:[{n, p, s, c}]}` (100 largest); `/api/sscancancel?id=` -> `{ok:true}`. `InProc.ROUTES` has `sscanp`, `sscannode`, `sscantop`.

### 12.8 Other devices (read-only, 2026-10-21)
The storage pill also works on **LANShare phones, SMB, FTP and SFTP** (not Root, not inside archives). `StorageScan.startRemote(dev, vpath, label)` builds the same `SNode` tree, so the whole screen works unchanged; `Scan.remote` / `Scan.dev` mark it, `StorageActivity.ro` (= archive or remote) switches off open / share / delete / reveal / multi-select. Results live in memory only (key `StorageScan.remoteKey`, never saved); Rescan starts a new one.
- **LANShare phone, new build** (fastest): the phone scans ITSELF (`/p/sscan`, native `StorageScan`), this phone polls `/p/sscanp` every 0.4 s and downloads the finished tree once with `/p/sscandl` (`StorageStore.encode` / `decode`, gzip, same format as the saved files). `/p/sscancancel` cancels. A scan bubble also shows on that phone.
- **LANShare phone, old build** (no route = 404): its `/p/walk` (one request, whole tree) is folded locally (`walkScan`).
- **SMB**: folder-per-task, 8 parallel `lsFast` calls on the one session. **FTP / SFTP**: same on 4 threads (= the 4-connection pool of `FtpPool` / `SPool`); depth cap 48 (symlink loops); an unlistable folder = "unreadable" like Android/data.
- UI: `usedPct()` / `pillSet()` in `ui.html` feed the pill (and native `NlHead` `u`) from `/api/space` for other devices; `LSAndroid.openStorageDev(dev, name, path)` -> `StorageActivity.intentDev`. The pill is absent where there is no space number (SMB server root, FTP without `space`).
- **Limits**: nothing can be opened / deleted from the analyzer for a remote scan; SMB / FTP speed depends on folder count (one round trip per folder); no byte-based percentage on folder scans; FTP has no free space so no pill there. Not compiled / not device-tested.

## 13. Performance

*Source: Settings > Debug: performance (branch `claude/debug-perf-tab`), reports taken 2026-10-20 on the user's phone. One device, one cold start per build - indicative; force-close and reopen the app before each startup report.*

### 13.1 Cold start (onCreate -> first screen)
| Build | Total | WebView + setup | Server start wait | Page load (ui.html) | Page done -> first screen |
|---|---|---|---|---|---|
| Baseline | 533 ms | 117 | **258** | 102 | 56 |
| Server started early (run 2) | 497 ms | 127 | 46 | **247** | 77 |
| + image engine deferred (run 3, merged) | **335 ms** | 95 | **38** | 157 | 45 |

**Net 533 -> 335 ms (-198 ms, ~-37 %).** `core.url` (server ready) is published 106 ms after process start (baseline `coreReady` 447 ms); 0 long tasks (run 2 had one 65 ms task during page load); `GET /api/folderstat` max 467 ms (baseline 965, run 2 2155); the image engine finishes loading at 981 ms (`core.clipLoaded`), ~590 ms after the first screen, off the critical path.
Marks of the current build (ms since process start): UI thread onCreate 54 -> fontInit 56 -> **webCreated 138 (WebView construction = 82 ms)** -> nativeViews 145 -> contentSet 145 -> permissionsAsked 147 -> loadStart 149. Server thread: threadStart 54 -> core.begin 56 -> cfgLoaded 85 (**29 ms** `Cfg.load`) -> locks 94 -> cleanup 95 -> pageAndFs 99 -> portBound 102 -> discoveryStarted 106 -> **url 106**. Page: loadStart 149 -> coreReady 187 (poll granularity) -> pageFinished 344 (157 ms) -> firstScreen 389.

### 13.2 Findings
- The server is **no longer on the critical path** (ready at 106 ms, before the WebView finishes building at 138 ms). Remaining early cost is WebView construction (82 of the 95 ms).
- Moving the heavy image-search work after `url` first hurt page load (247 vs 102 ms) because model load and watcher ran concurrently with the page load; deferring them until after the first screen fixed most of it (inferred from timings, consistent with run 3).
- Page load is still above baseline (157 vs 102 ms; main script starts at 116 vs 39 ms; DOM ready 152 vs 90 ms). **Unexplained.** Candidates: `WifiPrinters.start` and Discovery threads starting right after `url`; WebView renderer start; run-to-run variance.
- **No jank**: 0 long tasks; frame sample ~90 fps, 0 frames over 33 ms, worst 22 ms (WebView only; the native list is not counted). The UI page is cheap (main script 31-53 ms; ui.html 468 KB, 224 DOM nodes, 10 MB JS heap). Steady state is tiny (~1 s of main-thread time in 387 s: polling intervals, `nlLay`, `pollPeers`).
- Two slow background scans (do not block the UI thread): `GET /api/folderstat` (3 calls, avg 220-850 ms) and `GET /api/wifiprinters` (50-300 ms). Wasteful but cheap: `nlLay` / `nlChPush` / `nlSrPush` ~460 calls each in 8 s; `/api/peers` polled every few seconds.

### 13.3 Design questions answered
| Idea | Verdict |
|---|---|
| Rewrite ui.html fully native | At most ~100 ms of the now 335 ms; huge effort and regression risk. **Not worth it.** (An earlier estimate for a 100 % native UI: ~6,000-9,000 Kotlin lines, 1-2 weeks, no gain for storage reads / SMB / peers.) |
| Minify ui.html | Well under 20 ms. Low value. |
| ui.html growing to 1 MB | Main script run would grow from ~31-53 ms to ~70-120 ms; maintainability is the bigger problem. |
| Split ui.html into ten files | No speed gain; only maintainability. Safe if plain `<script src>` in the same order, startup block last, the server serves the files, debug wrappers installed after all files load. **Not yet checked**: how ui.html is served and whether Kotlin reads / patches it as text. |
